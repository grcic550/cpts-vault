## Internal password spraying from linux

Once we have a valid usernames list then we can perform password spraying attack. We can do this multiple ways with multiple tools.

We can use **rpcclient**

Here response with Authority Name means successful login so we can type command as this:

```bash
for u in $(cat valid_users.txt);do rpcclient -U "$u%Welcome1" -c "getusername;quit" 172.16.5.5 | grep Authority; done 
```

We can also use kerbrute and crackmapexec:

kerbrute:

```bash
kerbrute passwordspray -d inlanefreight.local --dc 172.16.5.5 valid_users.txt Welcome1
```

crackmapexec:

```bash
sudo crackmapexec smb 172.16.5.5 -u valid_users.txt -p Welcome1 | grep +
```

## Key Concepts:

- **Password Spraying:** An attack method where a single password (or a small list of common passwords) is tried against many different user accounts. This is done to avoid triggering account lockout policies that typically activate after multiple failed logins for a single user.
- **Local Administrator Password Reuse:** A common misconfiguration where the same password for a local administrator account is used across multiple workstations and servers. This allows an attacker who compromises one machine's local admin account to potentially gain administrative access to many others.

## Practical Application:

- **Tools for Domain Spraying:** The section demonstrates three tools for password spraying against domain accounts from a Linux host:
    - `rpcclient`: Uses a Bash `for` loop to iterate through a user list, identifying successful logins by filtering for the `Authority Name` in the output.
    - `kerbrute`: Uses the `passwordspray` command to efficiently test credentials against Kerberos.
    - `crackmapexec`: A versatile tool that can test a list of users against a single password over SMB, with successful logins marked by a `[+]`.
- **Local Admin Spraying:** `crackmapexec` can be used to spray a compromised local administrator's NTLM hash across an entire subnet. The `--local-auth` flag is critical to prevent domain account lockouts by ensuring it only attempts a local login on each machine.

## Watch Out For:

- **Account Lockouts:** Standard password spraying against domain accounts can still cause lockouts if not done carefully. The goal is "low and slow."
- **Noise:** Spraying an entire subnet with `crackmapexec` is a very "noisy" technique that will be easily detected by most security monitoring solutions. It is not suitable for stealthy operations.
- **Remediation:** The use of Microsoft's **LAPS (Local Administrator Password Solution)** is mentioned as an effective defense against local administrator password reuse.

## Internal Password Spraying - from Windows

There is a great tool for password spraying from windows **DomainPasswordSpray** tool is great for this purpose.

we can use it like this:

```powershell
PS C:\htb> Import-Module .\DomainPasswordSpray.ps1
PS C:\htb> Invoke-DomainPasswordSpray -Password Welcome1 -OutFile spray_success -ErrorAction SilentlyContinue
```

there are multiple ways to prevent this kind of events from happening like passwords leaking through password spraying attempts.

first one would be multi factor authentication. this is type of authentication that requires at least two factors from different categories like password and biometrics, or OTP(ONE TIME PASSWORD) or text message. That is extremely hard for hacker to get a hold on but not imposible. This type may prevent accessing the computer or better say target but it may still reveal credentails that can be used elsewhere.

also restricted access should be implemented and better password selection. our client or the administrator should also worry about DDOS attacks like intentionally missing passwords and locking down accounts which can bring down multiple users and stop work.

logging should be enabled to see and alert if there are any susspicions about logging on to the service. if there are a lot logon attempts and a lot of them failed in a short period of time, that could be a good indicator.

also the same should be done for kerberos pre-authentication, since there also can users be enumerated.
