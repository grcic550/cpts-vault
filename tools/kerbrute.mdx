## Kerbrute: choose the operation and read the result

Use the saved Kerberos username and authentication checks.

### What the result establishes

Distinguish a username-validity response from a successful password authentication result.

### Prerequisites and common failures

Username enumeration and password guessing are different modes; account lockout behavior and the selected realm/DC must be understood before credential attempts.

## Existing notes and worked examples

**Run on:** your Linux lab machine, from the folder containing the Kerbrute executable. If it is installed on your PATH, omit `./`.

```bash
./kerbrute --help
./kerbrute userenum --help
```

The first command lists the available tasks. The second lists the options for username enumeration. The domain, DC address, and username file must match the lab.

## Common problems

| Problem | Check |
| --- | --- |
| Executable not found | Check its filename, working directory, and whether it is on PATH. |
| KDC cannot be reached | Verify the DC address, domain name, DNS, route, and time. |
| Assuming enumeration leaves no logs | Kerberos requests can be logged. The task and account-lockout behavior differ from password testing. |
