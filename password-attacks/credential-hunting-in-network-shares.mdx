---
title: "Credential Hunting in Network Shares"
---

nearly all corporate environments use network shares by their employees to store and share data across teams. they can also become a goldmine of information if misconfigured.

common credential patterns include:
- keywords within files such as passwd, user, key, token and secret
- files with extensions such as .ini, .cnf, .ps1, .xlsx, .bat and .env
- files that include terms config, user, passw, cred or initial
- if we are trying to locate credentials within the INLANEFREIGHT.LOCAL domain, it may be helpful to search files containing string INLANEFREIGHT.LOCAL
- if we keywords should be localized based on the target. if we are attacking a german company we would search for "user" but rather "benutzer"
- we have to pay attention to what shares we are looking at since some are more important than other

we want to begin with basic command line searches like
```powershell
Get-ChildItem -Recurse -Include *.ext \\Server\Share | Select-String -Pattern ...
```

and so on, before scaling  up to more advanced tools. we will take look at how we can use MANSPIDER, Snaffler, SnafflePy and NetExec to automate and enhance this credential hunting process.

**Hunting from Windows**

First tool we are looking at is **Snaffler**.
This is a C# programm that, when run on domain-joined machine, automatically recognises network shares and searches for interesting files.

https://github.com/SnaffCon/Snaffler

Snaffler returns a large amount of information that would need to me manually reviewed. many results turn out to be "false-positives

useful parameters:

- -u --> retrieves list of users from Active Directory and searches for references to them in files
- -i and -n --> allow you to specify which shares should be included in the search

**PowerHuntShares**

Another powerfull tool that outputs results in HTML format. it doesn't necessarily need to be run on domain-joined machine and it is a powershell script.

if we want to use PowerHuntShares on windows we have to always run:

```powershell
# Bypass execution policy restrictions
Set-ExecutionPolicy -Scope Process Bypass

# Import module that exists in the current directory
Import-Module .\PowerHuntShares.psm1
```

after we transfer PowerHuntShares.psm1 to our target machine. then we can do something like this:
```powershell
Invoke-HuntSMBShares -Threads 100 -OutputDirectory C:\Users\Public
```

this is a basic PowerHuntShares scan.

**Hunting from Linux**

if we don't have access to domain-joined computer or we prefer to search for files remotely, then we can use MANSPIDER to scan for SMB shares from Linux. It offers many parameters that can be configured.

basic usage:

```bash
manspider <target> -u <user> -p <password> -c password
```

examples:
```bash
# search file contents for credentials
manspider 10.10.11.x -u mendres -p 'Password123' -c password creds secret

# search by filename
manspider 10.10.11.x -u mendres -p 'Password123' -f password backup

# filter by extension + content
manspider 10.10.11.x -u mendres -p 'Password123' -e xlsx docx txt -c password

# target a specific share
manspider 10.10.11.x -u mendres -p 'Password123' --share "Data" -c password
```

results:
```bash
~/.manspider/loot/
```

**NetExec**

NetExec can also be used to search through network shares using the --spider option. 

it can be run like so:

```bash
netexec smb <ip_target> -u <user> -p '<password>' -M spider_plus -o DOWNLOAD_FLAG=True --smb-timeout 60
```

- -o --> to download files

after that we need to search those files. it would be good to start with something like:

```bash
grep -ri "passw" .
```
this recursively searches for starting with passw and so on.

!!!IMPORTANT

that can still give a lot of files so remember from above this:

- Look for keywords within files such as `passw`, `user`, `token`, `key`, and `secret`.
- Search for files with extensions commonly associated with stored credentials, such as `.ini`, `.cfg`, `.env`, `.xlsx`, `.ps1`, and `.bat`.
- Watch for files with "interesting" names that include terms like `config`, `user`, `passw`, `cred`, or `initial`.
- If you're trying to locate credentials within the `INLANEFREIGHT.LOCAL` domain, it may be helpful to search for files containing the string `INLANEFREIGHT\`.
- Keywords should be localized based on the target; if you are attacking a German company, it's more likely they will reference a `"Benutzer"` than a `"User"`.
- Pay attention to the shares you are looking at, and be strategic. If you scan ten shares with thousands of files each, it's going to take a significant amount of time. Shares used by `IT employees` might be a more valuable target than those used for company photos.
  
  and filter with that in mind.
  
  some examples:
```bash
# the domain prefix (most reliable signal)
grep -ri "DOMAINNAME\\\\" .

# UPN format
grep -riE "[a-z]+@domain\.local" .

# runas / net use / Invoke-Command patterns - operators leak creds in commands
grep -riE "runas|net use|Invoke-Command|New-PSSession|ConvertTo-SecureString" .

# anything with "service account" / "svc_" in filenames
find . -iname "*svc*" -o -iname "*service*account*"
```

### 1. Domain-prefixed accounts (highest signal)
```bash
# the gold filter - DOMAIN\username syntax
grep -ri "${DOMAIN}\\\\" . 2>/dev/null

# UPN format
grep -riE "[a-zA-Z0-9._-]+@inlanefreight\.local" . 2>/dev/null
```

### 2. Cred-context keywords (medium-high signal)
```bash
# password / pwd / passwd with assignment
grep -riE "(pass(word)?|pwd|passwd)[[:space:]]*[:=][[:space:]]*\S+" . 2>/dev/null | grep -v Tools/

# variations - localized & abbreviated
grep -riE "passw|kennwort|contraseña|mot.de.passe|senha" . 2>/dev/null

# user/account context
grep -riE "(username|userid|account|login)[[:space:]]*[:=]" . 2>/dev/null | grep -v Tools/
```

### 3. Credential-handling patterns in scripts
```bash
# PowerShell cred patterns - extremely high signal
grep -riE "ConvertTo-SecureString|New-PSCredential|PSCredential|-AsPlainText" . 2>/dev/null
grep -riE "Invoke-Command.*-Credential|New-PSSession.*-Credential" . 2>/dev/null

# Windows command-line auth
grep -riE "net use .*\\\\.*/user:|runas.*\/user:|psexec.*-u " . 2>/dev/null

# connection strings
grep -riE "(server|data source|host)=.*;.*(user|uid)=.*;.*(pass|pwd)=" . 2>/dev/null
```

### 4. API/token/key patterns
```bash
grep -riE "(api[_-]?key|api[_-]?token|secret[_-]?key|access[_-]?token|bearer)[[:space:]]*[:=]" . 2>/dev/null
grep -riE "aws_access_key_id|aws_secret_access_key" . 2>/dev/null

# obvious high-entropy / base64-ish blocks near "key" or "secret"
grep -riE "[A-Za-z0-9+/]{40,}" . 2>/dev/null | grep -iE "key|secret|token"
```

### 5. Filename-based hunting
```bash
# files with interesting names
find . -type f \( -iname "*pass*" -o -iname "*cred*" -o -iname "*secret*" -o -iname "*config*" -o -iname "*backup*" -o -iname "*initial*" -o -iname "unattend*" -o -iname "sysprep*" -o -iname "autounattend*" \) 2>/dev/null | grep -v Tools/

# password manager databases
find . -type f \( -iname "*.kdbx" -o -iname "*.psafe3" -o -iname "*.1pux" \) 2>/dev/null

# files by interesting extension
find . -type f \( -iname "*.ini" -o -iname "*.cfg" -o -iname "*.conf" -o -iname "*.config" -o -iname "*.env" -o -iname "*.ps1" -o -iname "*.bat" -o -iname "*.cmd" -o -iname "*.vbs" -o -iname "*.xml" \) 2>/dev/null | grep -v Tools/
```

### 6. GPP / SYSVOL gold
```bash
# cpassword in any XML (GPP)
grep -ri "cpassword" . 2>/dev/null

# autologon in Registry.pol
strings SYSVOL/**/Registry.pol 2>/dev/null | grep -iE "DefaultPassword|DefaultUserName|AutoAdminLogon"
```

### 7. Show context around matches (super useful)
```bash
# show 3 lines of context - critical for matching user to password
grep -riE -C 3 "password" . 2>/dev/null | grep -v Tools/

# show filename + line + match
grep -rniE "passw" . 2>/dev/null | grep -v Tools/
```

### 8. One-liner that combines the most useful filters
```bash
grep -rniE "(${DOMAIN}\\\\|passw|pwd[[:space:]]*[:=]|cpassword|ConvertTo-SecureString|api[_-]?key|secret[_-]?key)" . 2>/dev/null | grep -v Tools/
```
### 9. Beyond plaintext — handle binary docs
```bash
# convert all office docs to txt
mkdir -p /tmp/converted
find . -type f \( -iname "*.docx" -o -iname "*.xlsx" -o -iname "*.pdf" -o -iname "*.pptx" \) 2>/dev/null | while read f; do
  libreoffice --headless --convert-to txt "$f" --outdir /tmp/converted >/dev/null 2>&1
done

grep -riE "passw|${DOMAIN}\\\\|cred" /tmp/converted/
```

### 10. Use ripgrep — much faster and handles more
```bash
sudo apt install ripgrep -y

# fast recursive search excluding noise
rg -i "password|cred|secret|${DOMAIN}\\\\" --glob '!Tools/**' --glob '!*.dll' --glob '!*.exe'

# show context
rg -i -C 2 "passw" --glob '!Tools/**'

# only filenames
rg -li "passw" --glob '!Tools/**'
```
### Recommended attack order

1. `grep -ri "${DOMAIN}\\\\"` ← **always start here**
2. `grep -ri "cpassword"` ← instant GPP win if present
3. Filename hunt: `find` for `*pass*`, `*cred*`, `*.kdbx`, `unattend*`
4. Context grep: `grep -riE -C 3 "passw"` to pair users with passwords
5. Convert binaries, repeat
6. Broad keyword sweep last (noisy)
