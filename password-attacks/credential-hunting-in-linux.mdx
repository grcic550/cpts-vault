hunting for credentials is one of the first steps that we have to do when obtaining access to a maching. for example if we have obtained reverse shell of a machine, first step would be to find credentials to elevate out privileges.

there are several sources that can provide us with credentials  that are put in four categories(this is not all of possible sources but most common ones):

files: files like config files, databases, notes, source code, cronjob, and SSH keys
History: logs and command line history
Memory: this includes cache and in-memory processing
Key-rings: such as browser stored credentials

enumerating all of these categories will increase our probability of successfully finding out credentials of existing users on this machine that we are targeting.  it is also useful and very important to know detailed about services that we encounter and interact with and what role they play since it can pivot us in right direction. for example if we have isolated database server it would be  logical to assume that not ordinary users have access to it and very little people actually do so information obtained there would be precious and possibly of high privilege.

**Files**
Core principle of Linux is that everything is a file so we should find and filter files to our need one by one.

configuration files are very precious since they are the core of functionalities of linux distributions. often the contain credentials that we can read. they also often have suffixes .config, .conf, .cnf but they can be renamed although this is not usually the case.

searching for configuration files can be done like this:

```bash
for l in $(echo ".conf .config .cnf");do echo -e "\nFile extensions: " $l; find / -name *$l 2>/dev/null | grep -v "lib\|fonts\|share\|core";done
```

optionally we can save output in a files and look at them later. we can also scan each file directly for the specified words and output contents. for example searching for words user, password and pass in files with file extension .cnf

```bash
for i in $(find / -name *.cnf 2>/dev/null | grep -v "doc\|lib");do echo -e "\nFile: " $i; grep "user\|password\|pass" $i 2>/dev/null | grep -v "\#";done

```
same principle can be applied for database search that can store credentials
example search:

```bash
for l in $(echo ".sql .db .*db .db*");do echo -e "\nDB File extension: " $l; find / -name *$l 2>/dev/null | grep -v "doc\|lib\|headers\|share\|man";done

```

same thing can be applied for notes that mostly end up in .txt file but can also be without extension. they can be on desktop but some may not so it would be useful to search and examine them file by file for specific processes on the system or even saved credentials.

example search:

```bash
find /home/* -type f -name "*.txt" -o ! -name "*.*"
```

searching for scripts is also important because they often contain highly sensitive information and processes. they can also contain credentials that are necessary to be able to call and execute processes automatically because otherwise administrator or developer would have to input password every time.

we can search like this:

```bash
 for l in $(echo ".py .pyc .pl .go .jar .c .sh");do echo -e "\nFile extension: " $l; find / -name *$l 2>/dev/null | grep -v "doc\|lib\|headers\|share";done
```

cronjobs could also be valuable source of information.
cronjobs are independant execution of commands, programs, scripts. These are divided into system wide area(/etc/crontab) and user-dependent executions.

some apllications and scripts require credentials to run so if developer or administrator set them wrong inside the cronjob then they could be used further more.

there are areas that are divided into time ranges: for example /etc/cron.daily, /etc/cron.hourly,...

scripts and files used by cron can also be found in /etc/cron.d

**Browser credentials**

Browsers store the passwords saved by the user in an encrypted form locally on the system to be reused. For example, the `Mozilla Firefox` browser stores the credentials encrypted in a hidden folder for the respective user. These often include the associated field names, URLs, and other valuable information.

For example, when we store credentials for a web page in the Firefox browser, they are encrypted and stored in `logins.json` on the system. However, this does not mean that they are safe there. Many employees store such login data in their browser without suspecting that it can easily be decrypted and used against the company.

For the browser we can use **LaZagne**, or we can locate the Firefox profile manually:

```bash
ls -l .mozilla/firefox/ | grep default
```

If we find an encrypted stored password, we can decrypt it with **firefox_decrypt.py**:

```bash
python3.9 firefox_decrypt.py
```

<Warning>
**firefox_decrypt.py requires **Python 3.9+** to run.**

</Warning>

## Key Takeaways

- On a fresh foothold, hunt credentials **before** anything else — they're the fastest path to privilege escalation and lateral movement.
- Four sources to sweep every time: **files** (configs, DBs, scripts, notes, SSH keys, cronjobs), **history** (shell + logs), **memory** (mimipenguin), and **key-rings** (browser stores).
- Understanding *what each service is and who uses it* tells you which finds are high-value (e.g. creds on an isolated DB server are likely privileged).
- Automate the sweep with `mimipenguin` and `LaZagne all`, but still grep configs/logs manually — tools miss context.
