## Check a supplied SNMP community list

**Run in:** Kali. **Requires:** An in-scope host and a bounded community candidate file; use the lab's permitted request rate.

```bash
onesixtyone -c communities.txt TARGET_IP
```

**What the result establishes:** A community response establishes that the specific candidate worked from this network position.

**Next check:** Compare UDP reachability and SNMP version; validate a responding community with a small snmpwalk query.

## If it fails

| Symptom | Check |
| --- | --- |
| A community guess gets no response | A non-response can be filtering, rate limiting or version restrictions; do not infer that every SNMP interface is absent. |

### SNMP (Port 161 UDP)

**Footprinting: Service-by-Service Lab Workflow**

```bash
# SNMPv2c — try common community strings
snmpwalk -v2c -c public <IP>
snmpwalk -v2c -c private <IP>
snmpwalk -v2c -c backup <IP>

# Brute force community strings
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <IP>

# SNMPv3 — try noAuthNoPriv (no password needed if misconfigured)
for user in root admin backup htb administrator; do
    echo "=== Trying: $user ==="
    snmpwalk -v3 -l noAuthNoPriv -u "$user" <IP> 2>/dev/null | head -3
done

# SNMPv3 with auth
snmpwalk -v3 -l authNoPriv -u <user> -a SHA -A "<password>" <IP>

# Filter useful info from SNMP dump
snmpwalk -v2c -c <community> <IP> | grep -i "user\|pass\|login\|htb"
```
