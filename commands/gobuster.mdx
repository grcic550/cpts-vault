## Current operation: Discover paths on a confirmed application

**Run in:** Kali. **Requires:** The intended virtual host, a readable path list and a known normal/not-found response.

```bash
gobuster dir -u http://HOST_FQDN/ -w paths.txt -o gobuster-paths.txt
```

**Read the result:** Choose directory, DNS or virtual-host enumeration deliberately and confirm each candidate's distinct response.

**If Wildcard or redirect responses flood the results:** Wordlists and extensions should fit the service; wildcard responses and incorrect hostnames can make results meaningless.

**Next check:** Compare response content and redirect destinations, then replay interesting paths in the same authenticated or unauthenticated context.

### Example 7: When AXFR is blocked: enumerate the hard way

Run in: **Saved lab example**.

```bash
# Individual record lookups
dig A target.com @<IP>            # host → IPv4
dig MX target.com @<IP>           # mail servers
dig NS target.com @<IP>           # name servers
dig TXT target.com @<IP>          # SPF/DKIM/verification strings
dig ANY target.com @<IP>          # everything the server will return at once

# Reverse lookups across a subnet (PTR records → hostnames)
dnsrecon -r 10.10.10.0/24 -n <IP>

# Subdomain brute force (guess names, keep the ones that resolve)
dnsenum --dnsserver <IP> -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt <domain>
gobuster dns -d <domain> -r <IP> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

### Complete Recon Methodology

**DNS and Web Reconnaissance: Full Workflow**

```text
Passive Recon (no target contact)
├── CT logs (crt.sh) → subdomains that ever had a cert
├── Google dorking → exposed files, login pages, config leaks
├── DNS enumeration → public DNS records
├── WHOIS / Shodan → infrastructure intel
├── .well-known URIs → security.txt, openid-config
└── theHarvester → emails, hosts from public sources

Active Recon (direct target interaction)
├── Zone transfer attempt (dig axfr) → dump DNS if misconfigured
├── VHost fuzzing (ffuf/gobuster) → hidden vhosts
├── Fingerprinting (WhatWeb/Nikto/Nmap) → tech stack
├── WAF detection (wafw00f) → security layer check
├── Web crawling (Scrapy/Burp/ZAP) → site map, links, files
├── robots.txt / sitemap.xml → hidden paths, structure
└── Directory brute force → unlisted pages

Post-Discovery
├── Add found vhosts/subdomains to /etc/hosts
├── Run CMS-specific scanners (WPScan, JoomScan)
├── Analyse extracted data (emails, comments, JS files)
├── Enumerate each attack surface
└── Prioritise dev/staging environments (weaker security)
```
