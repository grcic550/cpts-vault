## Separate login from listing and download

**Run in:** FTP client shell. **Requires:** A reachable FTP service and a permitted account or supported anonymous login; enter interactive commands after connecting.

```bash
ftp TARGET_IP
# After login, inside ftp:
binary
ls
get REMOTE_FILE LOCAL_FILE
```

**What the result establishes:** Separate control-channel login from directory listing and data transfer, then inspect file ownership and permissions.

**Next check:** Check the FTP data-connection mode/path, then verify the local file size and contents before following its clues.

## Commands

**Kali / FTP prompt**

```bash

```

## If it fails

| Symptom | Check |
| --- | --- |
| Login succeeds but listing or transfer hangs | Passive/active data connections have different network requirements; a successful login with a failed listing can be a data-channel problem. |

<Accordion title="Enumeration workflow">

### Enumeration workflow

**FTP Enumeration and File Access**

```bash
ftp <IP>                       # connect
# once logged in:
ls            # list files — but this hides dotfiles
ls -la        # ALWAYS do this — reveals hidden files like .ssh, .bash_history
pwd           # where am I
cd <dir>      # navigate
get <file>    # download one file
mget *        # download everything in the current dir
binary        # switch to binary mode before pulling non-text files (images, archives, keys)
lcd /tmp      # set the LOCAL download directory (fixes "Permission denied" on download)
put <file>    # UPLOAD a file (if you have write access — see below)
bye           # quit
```
