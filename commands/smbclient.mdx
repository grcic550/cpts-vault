## List shares with a known identity

**Run in:** Kali. **Requires:** An observed SMB endpoint and a supplied LAB/student identity

```bash
smbclient -L "//$TARGET_IP" -U 'LAB/student'
```

**What the result establishes:** Password prompt followed by a share list or a specific authentication/authorization error.

**Next check:** Select an actually advertised share and test access separately.

## Connect to one discovered share

**Run in:** Kali. **Requires:** Replace READABLE_SHARE with a real share; same identity as the listing

```bash
smbclient "//$TARGET_IP/READABLE_SHARE" -U 'LAB/student'
```

**What the result establishes:** An smb prompt establishes a connected share session; reading each file remains a separate check.

**Next check:** List files and retrieve one relevant readable file; record what it contains and its source.

## Verify access to the intended resource

**Run in:** Kali with lab name resolution. **Requires:** Observed server/share and the domain identity being investigated

```bash
smbclient '//SERVER_FQDN/KNOWN_SHARE' -U 'LAB/student'
```

**What the result establishes:** A connection or a resource-specific denial using the explicitly selected identity.

**Next check:** Record actual allowed operations and test the intended management service independently.

## List files in one authenticated share

**Run in:** Kali. **Requires:** A known share name, SMB connectivity and the correct account scope; enter the password at the prompt.

```bash
smbclient //TARGET_IP/SHARE -U 'DOMAIN/USER' -c 'ls'
```

**What the result establishes:** Separate listing shares, connecting to a share, listing a directory and reading a file under the current identity.

**Next check:** Check the specific share and path permissions; retrieve one relevant readable file and retain its original path with your notes.

## Commands

**Kali**

```bash
smbclient -L //TARGET_IP/ -N
smbclient //TARGET_IP/SHARE -U DOMAIN/USER
# Inside smbclient
ls
get file.zip
put file.zip
```

## If it fails

| Symptom | Check |
| --- | --- |
| NT_STATUS_LOGON_FAILURE | Check domain versus local account context and the supplied credentials without repeated guessing. |
| NT_STATUS_ACCESS_DENIED | Retain the successful login evidence and inspect the target share permission. |
| Authentication works but resource is denied | Inspect this resource authorization rather than assuming all domain credentials grant access. |
| Share listing works but this directory is denied | A share named in a listing may still deny access; use the correct domain/local username and actual share/path spelling. |
