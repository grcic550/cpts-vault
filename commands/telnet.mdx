**Run in:** Kali. **Requires:** A plaintext SMTP endpoint; use a TLS-capable client for implicit TLS or STARTTLS inspection.

**If No readable banner or the connection closes:** A TCP connection is not authentication; encrypted services require a TLS-aware client rather than sending plaintext into the TLS endpoint.

### IMAP (Port 143 / 993 SSL)

**Footprinting: Service-by-Service Lab Workflow**

```bash
# Connect plaintext
telnet <IP> 143

# Connect SSL
openssl s_client -connect <IP>:993

# Commands (A1, A2 are tags — use any prefix)
A1 LOGIN <username> <password>
A2 LIST "" "*"                    # list all mailboxes
A3 SELECT INBOX                   # open inbox
A4 SEARCH ALL                     # list message IDs
A5 FETCH 1 BODY[]                 # read full message
A6 FETCH 1:* (FLAGS SUBJECT)     # list subjects
A7 LOGOUT

# Quick test with curl
curl -k imaps://<IP> -u '<user>:<pass>'
curl -k imaps://<IP>/INBOX -u '<user>:<pass>'
```

### SMTP Status Code Lookup

**SMTP Status Code Lookup**

Context from the notebook: SMTP  (TCP  25 , also 465/587 encrypted) is the protocol that  sends/relays  mail. When you enumerate it manually ( telnet &lt;IP> 25 , then  HELO ,  VRFY ,  EXPN ,  RCPT TO ), the server replies with these  3-digit status codes . This sheet decodes them so you know whether a command worked, a user exists, or relay is allowed. (To  read  mail, see  Email Enumeration & Manipulation (POP3 - IMAP) .)

```text
telnet <IP> 25
```
