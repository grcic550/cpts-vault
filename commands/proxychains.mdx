## Send a TCP-connect probe through a SOCKS listener

**Run in:** Kali. **Requires:** A working SOCKS listener and a configuration whose ProxyList points to it; the upstream pivot can reach the target.

```bash
proxychains4 -f ./proxychains.conf nmap -sT -Pn -n -p 445 INTERNAL_IP
```

**What the result establishes:** Confirm the configured proxy type/address and test one TCP connection before using a larger enumeration tool.

**Next check:** Check the local proxy address, port and configuration; raw SYN, UDP and ICMP probes are not transported by this example.

## Commands

**Kali**

```bash
proxychains -q nmap -sT -Pn TARGET_IP
proxychains -q ssh USER@TARGET_IP
```

Configure the running SOCKS proxy in /etc/proxychains4.conf first; use the saved setup link below.

## If it fails

| Symptom | Check |
| --- | --- |
| Direct access works from the pivot but the proxied probe fails | This wraps compatible application connections; it does not transparently proxy raw SYN, ICMP or every UDP workflow, and DNS handling needs attention. |

### 1. SSH port forwarding (no tools needed)

**Pivoting and File Transfer: Field Reference**

```bash
# Dynamic (-D): a SOCKS proxy → reach the WHOLE subnet via proxychains
ssh -D 1080 jbetty@<DMZ_IP>
#   /etc/proxychains4.conf -> socks5 127.0.0.1 1080 ; then:
proxychains nxc smb 172.16.119.11 -u user -p pass

# Local (-L): map ONE internal service to a Kali local port (great for RDP)
ssh -L 13389:172.16.119.7:3389 jbetty@<DMZ_IP>
xfreerdp3 /v:127.0.0.1:13389 /u:bdavid /p:'...' /cert:ignore     # no proxychains

# Remote (-R): make a Kali service reachable FROM the pivot side (reverse)
ssh -R 8000:127.0.0.1:8000 jbetty@<DMZ_IP>      # DMZ's :8000 -> Kali's :8000
```
