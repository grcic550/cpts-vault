## Build a privilege hypothesis from the current token

On Windows, separate group membership, the process token, enabled privileges and the rights on a particular object. Administrator membership can still coexist with a filtered token. Start with identity and host facts, then investigate services, tasks, stored credentials and domain relationships.

### Identity, architecture and host context

```powershell
whoami /all
hostname
systeminfo
Get-LocalGroupMember Administrators
Get-CimInstance Win32_OperatingSystem | Select-Object Caption,Version,OSArchitecture
```

Retain the integrity level, group state and privilege list. A privilege name needs a compatible technique and process context; it does not make every similarly named lab recipe work on every Windows build.

### Services and scheduled tasks

```powershell
Get-CimInstance Win32_Service | Select-Object Name,StartName,State,PathName
Get-ScheduledTask | Select-Object TaskName,TaskPath,State
schtasks /query /fo LIST /v
```

For a promising service, inspect its configuration and both the service object's rights and executable path permissions:

```powershell
sc.exe qc SERVICE_NAME
sc.exe sdshow SERVICE_NAME
icacls "C:\Path\To\service.exe"
icacls "C:\Path\To"
```

A writable executable, writable parent directory, modifiable service configuration and permission to restart the service are different conditions. An unquoted path only becomes useful if the specific search path is controllable and the privileged service can actually execute it.

### Processes, network and credential leads

```powershell
Get-Process | Select-Object Id,ProcessName,Path
Get-NetTCPConnection -State Listen
cmdkey /list
Get-ChildItem C:\Users -Force
```

```powershell
# Search selected application folders after identifying a relevant service.
Get-ChildItem C:\inetpub,C:\ProgramData\APP -Recurse -File -ErrorAction SilentlyContinue | Where-Object Extension -in '.config','.ini','.xml','.json'
```

APP is a placeholder for an observed application directory. Read a selected configuration with its surrounding context; do not treat every password-like string as a live system credential. Saved credential targets, DPAPI material and plaintext configuration secrets have different reuse requirements.

### Prioritize a concrete boundary

| Finding | Verify before choosing a technique |
| --- | --- |
| Modifiable service | Exact service right, privileged identity, path and restart/trigger |
| Privileged scheduled task | Action, run level, controllable dependency and execution timing |
| Impersonation privilege | Current token, Windows build and technique-specific service conditions |
| Writable file/registry object | Who consumes it, with what privilege and when |
| Stored credential | Owning user, target, decryption context and current validity |
| Domain identity | Group/ACL relationships and a service that grants useful access |

Use Seatbelt, winPEAS or PowerUp to collect additional leads, then reproduce the selected condition with focused commands. Save the evidence before a lab change and verify the resulting process identity afterward. Restore changed service/task/file settings when the exercise requires cleanup.
