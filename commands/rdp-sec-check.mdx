## Inspect RDP security negotiation

**Run in:** Kali. **Requires:** The rdp-sec-check script with its dependencies and an RDP endpoint.

```bash
perl rdp-sec-check.pl TARGET_IP
```

**What the result establishes:** Interpret TLS, NLA and protocol configuration as characteristics of the RDP endpoint.

**Next check:** Compare TLS, NLA and client support; security negotiation does not establish that an account has RDP logon rights.

## RDP (Port 3389)

**Notebook example**

```bash
# Enumerate (get hostname, domain, NLA status — no creds needed)
nmap -sV -sC <IP> -p3389 --script rdp*

# Connect
xfreerdp /u:<user> /p:'<pass>' /v:<IP> /cert:ignore

# Security check
git clone https://github.com/CiscoCXSecurity/rdp-sec-check.git
./rdp-sec-check.pl <IP>
```

## If it fails

| Symptom | Check |
| --- | --- |
| RDP is reachable but a negotiation check fails | Configuration findings are separate from valid credentials and remote-interactive logon rights; connection failures may be network or policy related. |

### Security check & connecting

**Windows Remote Access: RDP, WinRM, and WMI**

```bash
# Check encryption / NLA posture
git clone https://github.com/CiscoCXSecurity/rdp-sec-check.git && cd rdp-sec-check
./rdp-sec-check.pl <IP>      # look for PROTOCOL_RDP:TRUE (weak) vs PROTOCOL_HYBRID:TRUE (NLA)

# Connect (Linux)
xfreerdp /u:<user> /p:"<pass>" /v:<IP> /cert:ignore
xfreerdp /u:<user> /p:"<pass>" /v:<IP> /dynamic-resolution
rdesktop -u <user> -p <pass> <IP>
```
