## Current operation: Open an authenticated file-transfer session

**Run in:** Kali. **Requires:** SSH reachability and an enabled SFTP subsystem with access to the intended path.

```bash
sftp USER@HOST_FQDN
```

**Read the result:** Use remote pwd/ls and local lpwd/lls to keep the two filesystems distinct before get or put.

**If The remote root differs from the operating-system path:** An SFTP-only account need not permit an interactive SSH shell or arbitrary port forwarding.

**Next check:** Inspect pwd and ls in the session; use get for the verified readable path and record any chroot restriction.

### Example 3: Mental Model — "What Do I Use When?"

Run in: **Saved lab example**.

```text
"I found an open port"
├── Is it a file share?    → SMB (445), NFS (2049), FTP (21)
├── Is it remote access?   → SSH (22), RDP (3389), WinRM (5985)
├── Is it a web server?    → HTTP (80/443) → fingerprint → fuzz
├── Is it email?           → SMTP (25), IMAP (143), POP3 (110)
├── Is it a database?      → MySQL (3306), MSSQL (1433), Oracle (1521)
├── Is it monitoring?      → SNMP (161), IPMI (623)
└── Not sure?              → nmap -sV -sC <IP> -p <port>

"I need to get files off the target"
├── Linux → scp/sftp (22)
├── Windows → SMB (445) or evil-winrm download
├── Web → wget/curl
└── Simple → python3 -m http.server (on target)

"I need to get files onto the target"
├── Linux → scp/sftp (22) or wget from attacker
├── Windows → SMB, certutil, PowerShell wget
├── Web upload → if upload form exists
└── Simple → python3 -m http.server (on attacker)

"I need a shell"
├── Linux → SSH (22)
├── Windows → Evil-WinRM (5985), PsExec (445), RDP (3389)
└── Either → reverse shell via exploit
```
