## Read a service's executable, account and security descriptor

**Run in:** Windows cmd.exe. **Requires:** A valid service name and permission to query its configuration/security descriptor.

```console
sc.exe qc SERVICE_NAME
sc.exe sdshow SERVICE_NAME
```

**What the result establishes:** Separate querying service configuration/security from changing or starting the service.

**Next check:** Check file/directory ACLs and the service DACL separately, then determine whether any legitimate restart/trigger can apply a change.

## List services

**Windows — cmd.exe or PowerShell**

```cmd
sc.exe query state= all
```

Keep the space after state=.

## Inspect service configuration

**Windows — cmd.exe or PowerShell**

```cmd
sc.exe qc SERVICE_NAME
```

BINARY_PATH_NAME is the command line; SERVICE_START_NAME is the service account.

## Read service permissions

**Windows — cmd.exe or PowerShell**

```cmd
sc.exe sdshow SERVICE_NAME
```

Displays SDDL for the service object; the binary file has separate permissions.

## If it fails

| Symptom | Check |
| --- | --- |
| The binary path looks writable but service control is denied | Use sc.exe in PowerShell to avoid aliases; service-control rights and permission to edit the executable are independent. |
| sc behaves like a file-writing command in PowerShell | Use sc.exe explicitly. In Windows PowerShell, sc can resolve to the Set-Content alias. |
