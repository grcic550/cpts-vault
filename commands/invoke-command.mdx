## Current operation: Verify one command through a remoting endpoint

**Run in:** Windows PowerShell. **Requires:** A reachable configured WinRM endpoint and an identity authorized for it.

```powershell
Invoke-Command -ComputerName HOST_FQDN -Credential DOMAIN\USER -ScriptBlock { whoami }
```

**Read the result:** Inspect the remote computer and identity that produced the returned objects.

**If Authentication works but the script or second-hop access fails:** PowerShell remoting, endpoint authorization and second-hop authentication are distinct; local credentials are not automatically delegated onward.

**Next check:** Separate endpoint permissions from script execution and delegated credentials; keep the returned identity and error details with the test.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Find Credentials in Network Shares

**Find Credentials in Network Shares**

```bash
# the domain prefix (most reliable signal)
grep -ri "DOMAINNAME\\\\" .

# UPN format
grep -riE "[a-z]+@domain\.local" .

# runas / net use / Invoke-Command patterns - operators leak creds in commands
grep -riE "runas|net use|Invoke-Command|New-PSSession|ConvertTo-SecureString" .

# anything with "service account" / "svc_" in filenames
find . -iname "*svc*" -o -iname "*service*account*"
```
