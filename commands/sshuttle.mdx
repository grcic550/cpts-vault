## sshuttle: choose the operation and read the result

Route selected traffic through an SSH host.

### What the result establishes

Check the chosen SSH pivot, routed subnet and actual destination connection from the workstation.

### Prerequisites and common failures

SSH access and subnet reachability from the pivot are prerequisites; its traffic model is not identical to a full VPN or SOCKS proxy.

### Example 1: Commands

Run in: **Kali**.

```bash
sshuttle -r USER@PIVOT_IP INTERNAL_SUBNET
```

### Example 2: sshuttle: Route a Subnet over SSH

Run in: **Saved lab example**.

```bash
sshuttle -r ubuntu@pivot 172.16.5.0/23           # route that subnet over SSH
sshuttle -r ubuntu@pivot 172.16.5.0/23 -x pivot  # exclude the pivot itself
# now use tools normally — no proxychains:
nmap -sT -Pn 172.16.5.19
```
