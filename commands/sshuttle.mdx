## Route a specific subnet through an SSH pivot

**Run in:** Kali. **Requires:** SSH access to a pivot with a supported Python interpreter and permission for local routing/firewall changes; choose a non-overlapping subnet.

```bash
sshuttle -r USER@PIVOT_IP INTERNAL_CIDR
```

**What the result establishes:** Check the chosen SSH pivot, routed subnet and actual destination connection from the workstation.

**Next check:** Check which traffic types are supported by the selected method and test the service from the pivot; handle DNS routing explicitly when using internal names.

## If it fails

| Symptom | Check |
| --- | --- |
| The SSH connection opens but the application is unreachable | SSH access and subnet reachability from the pivot are prerequisites; its traffic model is not identical to a full VPN or SOCKS proxy. |

### sshuttle: Route a Subnet over SSH

**sshuttle: Route a Subnet over SSH**

```bash
sshuttle -r ubuntu@pivot 172.16.5.0/23           # route that subnet over SSH
sshuttle -r ubuntu@pivot 172.16.5.0/23 -x pivot  # exclude the pivot itself
# now use tools normally — no proxychains:
nmap -sT -Pn 172.16.5.19
```
