## Map shares for one identity

**Run in:** Kali. **Requires:** An accepted SMB credential and a reachable SMB service.

```bash
smbmap -H TARGET_IP -d DOMAIN -u USER -p 'PASSWORD'
```

**What the result establishes:** Treat permission labels as a starting point and verify selected directory/file access manually.

**Next check:** Test the precise directory or file with that identity; keep share-level and file-level permissions separate.

## Commands

**Kali**

```bash
smbmap -H TARGET_IP -u USER -p 'PASSWORD'
smbmap -H TARGET_IP -u USER -p 'PASSWORD' -R 'SHARE'
```

## If it fails

| Symptom | Check |
| --- | --- |
| A listed permission does not allow an operation on a nested path | Reported write access is location-specific; it does not prove the share maps to an executable web path or an administrative context. |

<Accordion title="2. Listing and reading shares">

### 2. Listing and reading shares

**SMB Enumeration and Shares**

```bash
smbclient -L //<IP>/ -N                         # -N = no password; list shares via null session
smbclient //<IP>/<share> -U '<user>%<pass>'     # connect to a share interactively
#   inside smbclient:  ls / cd <dir> / get <file> / mget * / recurse ON; ls
smbmap -H <IP> -u <user> -p '<pass>'            # list shares WITH permissions in one view
smbmap -H <IP> -u <user> -p '<pass>' -R <share> # recurse a share and show the file tree
```
