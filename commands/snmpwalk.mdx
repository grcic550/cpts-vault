## Walk a bounded SNMP subtree

**Run in:** Kali. **Requires:** A permitted community string, compatible SNMP version and UDP reachability.

```bash
snmpwalk -v2c -c COMMUNITY TARGET_IP 1.3.6.1.2.1.1
```

**What the result establishes:** Start with a narrow relevant OID tree, then interpret returned types and values in their device context.

**Next check:** Record identity and management clues; select a relevant next subtree rather than repeatedly walking everything.

## Commands

**Kali**

```bash
snmpwalk -v2c -c COMMUNITY TARGET_IP
snmpwalk -v2c -c COMMUNITY TARGET_IP 1.3.6.1.2.1.25.4.2.1.2
```

## If it fails

| Symptom | Check |
| --- | --- |
| Timeout differs from an OID error or an empty subtree | Version, community/user security settings and permitted source address matter; timeout and an empty subtree are different results. |

### SNMP (Port 161 UDP)

**Footprinting: Service-by-Service Lab Workflow**

```bash
# SNMPv2c — try common community strings
snmpwalk -v2c -c public <IP>
snmpwalk -v2c -c private <IP>
snmpwalk -v2c -c backup <IP>

# Brute force community strings
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt <IP>

# SNMPv3 — try noAuthNoPriv (no password needed if misconfigured)
for user in root admin backup htb administrator; do
    echo "=== Trying: $user ==="
    snmpwalk -v3 -l noAuthNoPriv -u "$user" <IP> 2>/dev/null | head -3
done

# SNMPv3 with auth
snmpwalk -v3 -l authNoPriv -u <user> -a SHA -A "<password>" <IP>

# Filter useful info from SNMP dump
snmpwalk -v2c -c <community> <IP> | grep -i "user\|pass\|login\|htb"
```
