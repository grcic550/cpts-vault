## Create a loopback SOCKS proxy through SSH

**Run in:** Windows cmd.exe. **Requires:** An SSH account permitted to forward traffic and a verified server host key; the SSH host can reach intended destinations.

```console
plink.exe -ssh -N -D 127.0.0.1:9050 USER@SSH_HOST
```

**What the result establishes:** Determine whether the listener is local or remote and which host resolves/reaches the forwarding destination.

**Next check:** Check forwarding policy and the destination from the SSH host, then configure a SOCKS-aware client to use the local listener.

## If it fails

| Symptom | Check |
| --- | --- |
| SSH authentication works but proxy destinations fail | Use the correct SSH identity and verify the server key; confusing forwarding direction often makes a healthy SSH session look like a broken tunnel. |
