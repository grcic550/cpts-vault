## dnsenum: choose the operation and read the result

Commands and examples collected from your dnsenum notes.

### What the result establishes

Separate nameserver discovery, zone-transfer results, brute-force answers and reverse-lookup findings.

### Prerequisites and common failures

Wildcard DNS and stale records can inflate results; verify names with the intended authoritative or internal resolver.

### Example 1: Phase 0 — External / Infrastructure Recon

Run in: **Notebook example**. Saved as written; may include lab values or terminal output.

```bash
dig ns <domain> @<nameserver>      # nameservers
dig any <domain> @<nameserver>     # everything the server will tell you
dig axfr <domain> @<nameserver>    # zone transfer — jackpot if allowed
dnsenum --dnsserver <ns> --enum -f ~/subdomains.list -o found_subdomains.txt <domain>
```

### When AXFR is blocked: enumerate the hard way

**DNS Enumeration and Zone Transfers**

```bash
# Individual record lookups
dig A target.com @<IP>            # host → IPv4
dig MX target.com @<IP>           # mail servers
dig NS target.com @<IP>           # name servers
dig TXT target.com @<IP>          # SPF/DKIM/verification strings
dig ANY target.com @<IP>          # everything the server will return at once

# Reverse lookups across a subnet (PTR records → hostnames)
dnsrecon -r 10.10.10.0/24 -n <IP>

# Subdomain brute force (guess names, keep the ones that resolve)
dnsenum --dnsserver <IP> -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt <domain>
gobuster dns -d <domain> -r <IP> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```
