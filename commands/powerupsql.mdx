## Current operation: Read SQL instance identity with an integrated session

**Run in:** Windows PowerShell. **Requires:** PowerUpSQL and a Windows identity permitted to authenticate to the selected SQL instance.

```powershell
Import-Module .\PowerUpSQL.ps1
Get-SQLQuery -Instance 'HOST_FQDN,1433' -Query 'SELECT SYSTEM_USER, DB_NAME();'
```

**Read the result:** Establish SQL instance discovery, login context, roles and impersonation/linked-server relationships as separate findings.

**If The instance is discoverable but the query cannot authenticate:** A reachable instance or database login does not imply sysadmin; actions that change server configuration need a verified prerequisite.

**Next check:** Establish the accepted SQL/Windows login context, then inspect roles and object permissions before following linked-server or impersonation leads.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.
