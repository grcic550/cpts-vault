## Current operation: Read the ACL on one executable or directory

**Run in:** Windows cmd.exe. **Requires:** The actual object path and read access to its security descriptor.

```console
icacls "C:\APP\service.exe"
```

**Read the result:** Read the principal, rights, inheritance and scope of each ACE on the exact file and its parent directories.

**If A writable parent directory is mistaken for direct file write access:** Writable content, writable parent directories and permission to change the ACL are different capabilities; deny/inherited entries need interpretation.

**Next check:** Check file and parent ACLs, inheritance and the effective current principal; then verify whether a privileged process consumes the object.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Example 2: Inspect a directory

Run in: **Windows — cmd.exe**. F = full control, M = modify, RX = read/execute, W = write, (I) = inherited. Evaluate the current user and group memberships too.

### EoP - Incorrect permissions in services

**Windows Privilege Escalation: Full Checklist**

```powershell
$ for /f "tokens=2 delims='='" %a in ('wmic service list full^|find /i "pathname"^|find /i /v "system32"') do @echo %a >> c:\windows\temp\permissions.txt
$ for /f eol^=^"^ delims^=^" %a in (c:\windows\temp\permissions.txt) do cmd.exe /c icacls "%a"

$ sc query state=all | findstr "SERVICE_NAME:" >> Servicenames.txt
FOR /F %i in (Servicenames.txt) DO echo %i
type Servicenames.txt
FOR /F "tokens=2 delims= " %i in (Servicenames.txt) DO @echo %i >> services.txt
FOR /F %i in (services.txt) DO @sc qc %i | findstr "BINARY_PATH_NAME" >> path.txt
```
