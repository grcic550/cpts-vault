## Identify the artifact before selecting a cracking command

Password recovery begins with the exact format, source and account association. NT hashes, NetNTLM challenge/responses, Kerberos artifacts and encrypted archives use different inputs and modes. A file extension or a tool's guess is not enough to establish the format.

### Inspect and prepare a working copy

```bash
file acquired-artifact
head -n 2 hashes.txt
hashcat --example-hashes
john --list=formats
```

Inspect sensitive material locally in the lab. Preserve the untouched original, username mapping and extraction command. Tools such as the relevant `*2john` converter extract a recovery input from an archive/document/key file; the converter does not itself recover the password.

### Choose the exact algorithm or artifact mode

| Example artifact | Hashcat mode shown in these notes |
| --- | --- |
| NT hash | 1000 |
| NetNTLMv2 challenge/response | 5600 |
| Kerberos TGS RC4 ($krb5tgs$23$) | 13100 |
| Kerberos AS-REP RC4 ($krb5asrep$23$) | 18200 |

The prefix and full field structure must match. AES Kerberos artifacts and other encryption schemes require different modes. A NetNTLM response is not an NT hash suitable for pass-the-hash authentication.

### Start with a bounded candidate set

```bash
# Example for NT hashes only:
hashcat -m 1000 hashes.txt WORDLIST
hashcat -m 1000 hashes.txt --show

# John with an explicitly identified NT format:
john --format=NT --wordlist=WORDLIST hashes.txt
john --format=NT --show hashes.txt
```

Use a relevant wordlist and record its identity. If the lab supplies a known naming/password pattern, a targeted rule or mask can test that hypothesis; an unexplained enormous keyspace wastes time and makes the result hard to interpret.

### Read status and recovery separately

“No hashes loaded” is an input/parser problem. “Exhausted” means the selected candidate space completed without additional recovery. A potfile may already contain a result, so inspect `--show` before assuming the tool skipped work. Unsupported compute devices and memory limits are execution-environment problems, not evidence that the hash is uncrackable.

A recovered value still needs its source account/domain and one relevant service validation. Do not use a recovered application's password as a system password without evidence of reuse. Record the successful or failed validation and keep the recovered secret associated with its exact original artifact.

## Hashcat: choose the operation and read the result

Crack a hash offline using its correct mode.

### What the result establishes

Identify the artifact format and hash mode first; read recovered versus exhausted status and use --show on the original hash file.

### Prerequisites and common failures

An exhausted wordlist does not prove the password is strong or the hash invalid; the wrong mode, encoding or malformed input can invalidate the attempt.

### Example 1: Commands

Run in: **Kali**.

```bash
hashcat -m HASH_MODE hashes.txt /usr/share/wordlists/rockyou.txt
hashcat -m HASH_MODE hashes.txt --show
# Common modes: NTLM 1000; NetNTLMv2 5600; Kerberoast 13100; AS-REP 18200
```

### Example 2: Hashcat: Modes, Rules, and Masks

Run in: **Saved lab example**.

```bash
hashcat -m <mode> hashes.txt /usr/share/wordlists/rockyou.txt
hashcat -m 0 hashes.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule   # +rules
hashcat -m <mode> hashes.txt -a 3 '?u?l?l?l?l?d?d'                            # mask/brute
hashcat --show -m <mode> hashes.txt                                          # recovered
```
