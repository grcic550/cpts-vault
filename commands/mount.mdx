## Inspect a permitted export read-only

**Run in:** Linux shell. **Requires:** The exact export path, client access permission and local mount privilege; use a separate empty mount point.

```bash
mkdir -p /tmp/nfs-review
sudo mount -t nfs -o ro TARGET_IP:/EXPORT /tmp/nfs-review
ls -lan /tmp/nfs-review
sudo umount /tmp/nfs-review
```

**What the result establishes:** Confirm the remote export, local mountpoint, selected filesystem and actual mounted options before reading data.

**Next check:** Compare numeric UID/GID ownership and server-side mapping; do not assume client root bypasses export permissions.

## Commands

**Kali**

```bash
mkdir -p /tmp/nfs
sudo mount -t nfs TARGET_IP:/EXPORT /tmp/nfs -o nolock
ls -la /tmp/nfs
sudo umount /tmp/nfs
```

## If it fails

| Symptom | Check |
| --- | --- |
| The export mounts but file reads are denied | Use read-only inspection where appropriate; client restrictions, UID/GID mapping, root squashing and protocol versions affect access. |

### NFS (Port 2049)

**Footprinting: Service-by-Service Lab Workflow**

```bash
# List available shares
showmount -e <IP>

# Mount a share
mkdir /tmp/target-NFS
sudo mount -t nfs <IP>:/<share> /tmp/target-NFS

# Browse (use sudo — NFS permissions may block normal user)
sudo ls -la /tmp/target-NFS/<folder>
sudo cat /tmp/target-NFS/<folder>/file.txt

# Unmount when done (important — stale mounts freeze your terminal)
sudo umount -f /tmp/target-NFS
sudo umount -l /tmp/target-NFS   # if -f doesn't work
```
