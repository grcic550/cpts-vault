## Serve a dedicated authenticated transfer directory

**Run in:** Kali. **Requires:** A dedicated folder, a free SMB listening port and a Windows client that can reach Kali; choose a temporary transfer credential.

```bash
mkdir -p ./transfer
sudo impacket-smbserver share ./transfer -smb2support -user transfer -password 'TRANSFER_PASSWORD'
```

**What the result establishes:** Verify the share name, served directory and incoming connection, then confirm the requested file on both ends.

**Next check:** Check existing Windows connections, credentials and SMB policy, then copy a small file before transferring the required artifact.

## Commands

**Kali**

```bash
mkdir -p ~/transfer
sudo impacket-smbserver share ~/transfer -smb2support -user transfer -password 'TRANSFER_PASSWORD'
```

## If it fails

| Symptom | Check |
| --- | --- |
| Windows reaches the host but refuses the share connection | Choose a directory intentionally; SMB client policy, authentication and port reachability can prevent transfers even when the server is listening. |
