## Check a zone transfer against its nameserver

**Run in:** Kali. **Requires:** A known zone name and its authoritative nameserver; this is a transfer request, not a recursive lookup.

```bash
dig @NAMESERVER_IP DOMAIN_FQDN AXFR
```

**What the result establishes:** Record the queried name, record type, selected resolver and response status before using a hostname as a lead.

**Next check:** Retain names and records if returned; otherwise continue targeted DNS record and hostname enumeration.

## Commands

**Kali**

```bash
dig @DC_IP MS01.DOMAIN A
dig @DC_IP DOMAIN AXFR
dig @DC_IP _ldap._tcp.dc._msdcs.DOMAIN SRV
```

## If it fails

| Symptom | Check |
| --- | --- |
| Transfer is refused while address lookups work | NXDOMAIN, no matching answer and timeout are different results; zone transfers require the right authoritative server and permission. |

<Accordion title="When AXFR is blocked: enumerate the hard way">

### When AXFR is blocked: enumerate the hard way

**DNS Enumeration and Zone Transfers**

```bash
# Individual record lookups
dig A target.com @<IP>            # host → IPv4
dig MX target.com @<IP>           # mail servers
dig NS target.com @<IP>           # name servers
dig TXT target.com @<IP>          # SPF/DKIM/verification strings
dig ANY target.com @<IP>          # everything the server will return at once

# Reverse lookups across a subnet (PTR records → hostnames)
dnsrecon -r 10.10.10.0/24 -n <IP>

# Subdomain brute force (guess names, keep the ones that resolve)
dnsenum --dnsserver <IP> -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt <domain>
gobuster dns -d <domain> -r <IP> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```
