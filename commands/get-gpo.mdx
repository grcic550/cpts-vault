## Inspect permissions on one named GPO

**Run in:** Windows PowerShell. **Requires:** The GroupPolicy module, the intended GPO and rights to read its permissions.

```powershell
Import-Module GroupPolicy
Get-GPPermission -Name 'GPO_NAME' -All
```

**What the result establishes:** Inspect the GPO identity, report, links and applicable scope before relating it to a host or user.

**Next check:** Check links, inheritance, security/WMI filtering and policy-file permissions before concluding that the setting applies.

## List policies

**Windows PowerShell**

```powershell
Import-Module GroupPolicy
Get-GPO -All | Select-Object DisplayName,Id,GpoStatus
```

## Inspect permissions

**Windows PowerShell**

```powershell
Get-GPPermission -Name 'GPO_NAME' -All
```

## Applied computer policy

**Elevated Windows cmd.exe or PowerShell**

```text
gpresult /r /scope computer
```

## If it fails

| Symptom | Check |
| --- | --- |
| A principal can edit the GPO but the policy does not affect the target | A writable GPO object, writable policy files and permission to link it are different relationships; filtering can prevent application. |
