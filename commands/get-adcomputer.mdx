**Requires:** The ActiveDirectory PowerShell module and connectivity/authentication to AD. For DNS alone, use Resolve-DnsName.

## Inspect a computer's hostname and delegation configuration

**Run in:** Windows PowerShell. **Requires:** A valid directory computer identity and permission to read the requested properties.

```powershell
Import-Module ActiveDirectory
Get-ADComputer -Identity HOSTNAME -Properties DNSHostName,OperatingSystem,msDS-AllowedToDelegateTo
```

**What the result establishes:** Use DNSHostName, OS, SID and relevant delegation attributes to characterize a computer object.

**Next check:** Resolve the hostname, confirm reachability and inspect the effective delegation relationship before relying on the configuration.

## Resolve one computer object

**Windows PowerShell**

```powershell
Import-Module ActiveDirectory
Get-ADComputer -Identity MS01 -Properties DNSHostName,IPv4Address | Select-Object Name,DNSHostName,IPv4Address
```

## List computer names

**Windows PowerShell**

```powershell
Get-ADComputer -Filter * -Properties DNSHostName | Select-Object Name,DNSHostName
```

## If it fails

| Symptom | Check |
| --- | --- |
| The object exists but its host is offline or its SPN path fails | The directory object may be stale or offline; an attribute describes configuration, not necessarily reachable or currently effective access. |

### Query users, computers, groups, and trusts

**Active Directory Enumeration: Quick Reference**

```powershell
Import-Module ActiveDirectory
Get-ADDomain
Get-ADForest
Get-ADUser -Filter * -Properties Description | Select-Object SamAccountName,Enabled,Description
Get-ADComputer -Filter * -Properties OperatingSystem | Select-Object Name,DNSHostName,OperatingSystem
Get-ADPrincipalGroupMembership USERNAME | Select-Object Name
Get-ADGroupMember 'Domain Admins' -Recursive
Get-ADTrust -Filter *
```
