## Current operation: Inspect a computer's hostname and delegation configuration

**Run in:** Windows PowerShell. **Requires:** A valid directory computer identity and permission to read the requested properties.

```powershell
Import-Module ActiveDirectory
Get-ADComputer -Identity HOSTNAME -Properties DNSHostName,OperatingSystem,msDS-AllowedToDelegateTo
```

**Read the result:** Use DNSHostName, OS, SID and relevant delegation attributes to characterize a computer object.

**If The object exists but its host is offline or its SPN path fails:** The directory object may be stale or offline; an attribute describes configuration, not necessarily reachable or currently effective access.

**Next check:** Resolve the hostname, confirm reachability and inspect the effective delegation relationship before relying on the configuration.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

## Get-ADComputer: choose the operation and read the result

Read computer objects with the Windows Active Directory module.

### What the result establishes

Use DNSHostName, OS, SID and relevant delegation attributes to characterize a computer object.

### Prerequisites and common failures

The directory object may be stale or offline; an attribute describes configuration, not necessarily reachable or currently effective access.

The ActiveDirectory PowerShell module and connectivity/authentication to AD. For DNS alone, use Resolve-DnsName.

### Example 1: Resolve one computer object

Run in: **Windows PowerShell**.

```powershell
Import-Module ActiveDirectory
Get-ADComputer -Identity MS01 -Properties DNSHostName,IPv4Address | Select-Object Name,DNSHostName,IPv4Address
```

### Example 2: List computer names

Run in: **Windows PowerShell**.

```powershell
Get-ADComputer -Filter * -Properties DNSHostName | Select-Object Name,DNSHostName
```
