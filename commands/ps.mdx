## Inspect process owners, parent IDs and arguments

**Run in:** Linux target. **Requires:** A procps-compatible ps implementation and process visibility in the current namespace.

```bash
ps -eo user,pid,ppid,args --forest
```

**What the result establishes:** Read process owner, arguments and parent relationships to understand running services and recurring jobs.

**Next check:** Observe repeatedly and correlate with scheduler/service configuration; process arguments are leads, not proof of writable configuration.

## 5. Processes & jobs

**Notebook example**

```bash
Ctrl+c              # kill the running foreground command
Ctrl+z              # SUSPEND it (pauses, gives prompt back)
bg                  # resume the suspended job in background
fg                  # bring it back to foreground
jobs                # list background/suspended jobs
cmd &               # run in background from the start
ps aux | grep ssh   # find a process
kill <PID>          # terminate by PID
kill -9 <PID>       # force kill
pkill nmap          # kill by name
htop                # interactive process viewer (apt install htop)
```

Saved as written; may include lab values or terminal output.

## If it fails

| Symptom | Check |
| --- | --- |
| The process tree omits short-lived or other-namespace workloads | Process visibility can be restricted and snapshots miss short-lived tasks; combine repeated observations with scheduler/service configuration. |

### Identifying Your Shell

**Shells, Payloads, and Interactive TTYs**

```bash
# Linux — check running processes
ps
#   PID TTY      TIME CMD
#  4232 pts/1    00:00:00 bash     ← this tells you it's bash

# Linux — check SHELL environment variable
env | grep SHELL
# SHELL=/bin/bash

# PowerShell — version check (works on both Windows and Linux)
$PSVersionTable
# If this returns version info → you're in PowerShell
# If it errors → you're in cmd.exe or bash
```
