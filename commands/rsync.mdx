## Current operation: Inspect a named rsync module before transfer

**Run in:** Kali. **Requires:** An rsync daemon endpoint and, for the second command, an observed module name.

```bash
rsync rsync://TARGET_IP/
rsync --list-only rsync://TARGET_IP/MODULE/
```

**Read the result:** List the available module and readable paths, then choose a specific source and destination for a controlled transfer.

**If A module is advertised but listing is denied:** Trailing slashes change copy layout, and --delete can remove destination files; a module listing is not write permission.

**Next check:** Check module authentication and path permissions; copy selected files only after understanding what the listing exposes.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Example 2: Rsync

Run in: **Saved lab example**.

```bash
sudo nmap -sV -p 873 <IP>
nc -nv <IP> 873          # then send: @RSYNCD: 31.0  /  #list   to enumerate modules

rsync -av --list-only rsync://<IP>/<share>     # list a share's contents
rsync -av rsync://<IP>/<share> ./loot/          # download everything
rsync -av -e "ssh -p2222" rsync://<IP>/<share> ./loot/   # over SSH, custom port
```
