## Identify the Linux route to a destination

**Run in:** Linux shell. **Requires:** A shell on the actual source host and the destination address.

```bash
ip -br address
ip route get TARGET_IP
```

**What the result establishes:** Read addresses, prefixes and the selected route together; use route get to identify the actual egress decision.

**Next check:** Compare VPN and internal prefixes; test the service from the chosen interface before introducing a tunnel.

## Commands

**Kali/Linux**

```bash
ip address
ip route
```

## If it fails

| Symptom | Check |
| --- | --- |
| The selected interface or source address is unexpected | Multiple interfaces and overlapping VPN/internal subnets can select an unexpected route even when the destination address looks correct. |
