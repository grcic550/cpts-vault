## Request a ticket for one service principal

**Run in:** Kali. **Requires:** A valid credential or configured cache and an SPN registered for the intended service.

```bash
impacket-getST -spn cifs/HOST_FQDN -dc-ip DC_IP 'DOMAIN_FQDN/USER'
```

**What the result establishes:** Inspect the requested SPN and returned service identity before using the cache with a client.

**Next check:** Check the ticket principal and service hostname, then verify that identity's resource permission; S4U impersonation is a separate, conditional operation.

## Commands

**Kali**

```bash
impacket-getST -spn cifs/TARGET_FQDN -impersonate USER_TO_IMPERSONATE -dc-ip DC_IP 'DOMAIN/SERVICE_ACCOUNT:PASSWORD'
```

Requires the relevant delegation configuration/rights; credentials alone do not grant impersonation.

## If it fails

| Symptom | Check |
| --- | --- |
| A service ticket is returned but the resource denies access | Ordinary service-ticket requests and S4U impersonation require different rights; delegation configuration and protected-account restrictions can prevent impersonation. |
