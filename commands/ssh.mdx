## Establish an SSH session using a known account

**Run in:** Kali. **Requires:** SSH reachability and an accepted authentication method; verify the host key against the expected host.

```bash
ssh USER@HOST_FQDN
```

**What the result establishes:** Verify the server host key, selected account and actual remote identity before interpreting shell behavior.

**Next check:** Inspect the account's permitted session type; use the appropriate transfer or forwarding mode only if the server allows it.

## Commands

**Kali**

```bash
ssh USER@TARGET_IP
chmod 600 id_rsa
ssh -i id_rsa USER@TARGET_IP
```

## If it fails

| Symptom | Check |
| --- | --- |
| Authentication succeeds but the requested shell is unavailable | A valid account may be restricted to SFTP, a forced command or forwarding only; local and remote forwarding directions are easy to confuse. |

<Accordion title="1. SSH port forwarding (no tools needed)">

### 1. SSH port forwarding (no tools needed)

**Pivoting and File Transfer: Field Reference**

```bash
# Dynamic (-D): a SOCKS proxy → reach the WHOLE subnet via proxychains
ssh -D 1080 jbetty@<DMZ_IP>
#   /etc/proxychains4.conf -> socks5 127.0.0.1 1080 ; then:
proxychains nxc smb 172.16.119.11 -u user -p pass

# Local (-L): map ONE internal service to a Kali local port (great for RDP)
ssh -L 13389:172.16.119.7:3389 jbetty@<DMZ_IP>
xfreerdp3 /v:127.0.0.1:13389 /u:bdavid /p:'...' /cert:ignore     # no proxychains

# Remote (-R): make a Kali service reachable FROM the pivot side (reverse)
ssh -R 8000:127.0.0.1:8000 jbetty@<DMZ_IP>      # DMZ's :8000 -> Kali's :8000
```
