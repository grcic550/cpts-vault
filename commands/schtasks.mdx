## Current operation: Inspect a named scheduled task's exact definition

**Run in:** Windows cmd.exe. **Requires:** The correct task path and permission to read it.

```console
schtasks /query /tn "\TASK_NAME" /xml
```

**Read the result:** Read task identity, action, schedule and triggers, then inspect the referenced files.

**If The task is visible but its action does not run in your context:** A readable task does not imply permission to modify it; a writable script needs a privileged execution trigger to form a path.

**Next check:** Read principal, run level, action, arguments and trigger; inspect the referenced file and directory ACLs before judging exploitability.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### PHASE B — PrivEsc enumeration

**Windows Post-Exploitation: Field Reference**

```cmd
:: Unquoted service paths (space in path + no quotes = hijack)
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /iv "c:\windows\\" | findstr /iv """
:: AlwaysInstallElevated (any .msi runs as SYSTEM if both keys = 1)
reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
:: Stored AutoLogon creds (cleartext!)
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultPassword
:: Saved creds you can reuse without knowing them
cmdkey /list
:: Scheduled tasks (look for writable scripts run by SYSTEM)
schtasks /query /fo LIST /v | findstr /i "TaskName Run As User Task To Run"
```
