## Connect using a domain identity

**Run in:** Kali. **Requires:** Reachable SQL Server and a domain account accepted by that instance; password is prompted.

```bash
impacket-mssqlclient -windows-auth 'DOMAIN/USER@TARGET_IP'
```

**What the result establishes:** First distinguish SQL authentication from Windows authentication, then read the server, database and effective login.

**Next check:** Inspect SYSTEM_USER, database membership and the exact object permission before attempting OS actions.

## SQL login — password prompted

**Kali**

```bash
impacket-mssqlclient 'USER@TARGET_IP'
```

## Inside the SQL prompt

**MSSQL prompt**

```sql
help
SELECT SYSTEM_USER;
SELECT IS_SRVROLEMEMBER('sysadmin');
SELECT name FROM sys.databases;
```

## OS command — requires appropriate SQL privileges

**Impacket SQL prompt**

```text
enable_xp_cmdshell
xp_cmdshell whoami
```

Enables xp_cmdshell on the server.

## If it fails

| Symptom | Check |
| --- | --- |
| Login succeeds but a query is denied | A database login does not imply sysadmin, impersonation rights, linked-server access or operating-system execution. |
| Login failed | Confirm SQL authentication versus Windows authentication. Use -windows-auth for the domain account form; verify the SQL instance and port. |
| xp_cmdshell permission denied | A SQL login does not imply sysadmin or OS command execution rights. Check the role query before trying the optional command-execution block. |
