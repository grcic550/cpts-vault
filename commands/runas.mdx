## Current operation: Launch a local process under another Windows identity

**Run in:** Windows cmd.exe. **Requires:** A known password, an interactive password prompt and an identity allowed the relevant logon; this example is not /netonly.

```console
runas /user:DOMAIN\USER cmd.exe
```

**Read the result:** Confirm the new process identity and distinguish local-token behavior from outbound network credentials.

**If The process starts but expected network or administrative access is missing:** /netonly keeps local identity while supplying outbound credentials; a launched process does not prove those credentials have authenticated anywhere.

**Next check:** Run whoami /all inside it and test the specific resource; local identity, elevation and outbound credentials are separate properties.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Find Credentials in Network Shares

**Find Credentials in Network Shares**

```bash
# the domain prefix (most reliable signal)
grep -ri "DOMAINNAME\\\\" .

# UPN format
grep -riE "[a-z]+@domain\.local" .

# runas / net use / Invoke-Command patterns - operators leak creds in commands
grep -riE "runas|net use|Invoke-Command|New-PSSession|ConvertTo-SecureString" .

# anything with "service account" / "svc_" in filenames
find . -iname "*svc*" -o -iname "*service*account*"
```
