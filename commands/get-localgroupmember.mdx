## Resolve local Administrators membership

**Run in:** Windows PowerShell. **Requires:** The LocalAccounts module on a supported Windows host; the well-known SID avoids localized group-name assumptions.

```powershell
Get-LocalGroupMember -SID 'S-1-5-32-544'
```

**What the result establishes:** Record members and resolved principal sources for the selected local group.

**Next check:** Resolve nested domain membership and inspect whoami /all in the actual session; group membership does not prove an elevated process.

## Local administrators

**Windows PowerShell**

```powershell
Get-LocalGroupMember -Group 'Administrators' | Format-Table Name,PrincipalSource
```

Use the localized group name on non-English systems.

## Find available group names

**Windows PowerShell**

```powershell
Get-LocalGroup
```

## If it fails

| Symptom | Check |
| --- | --- |
| A domain principal is listed but its current token is restricted | Domain groups can grant indirect access, and current tokens can predate membership changes; a failed SID resolution can hide a member's display name. |
| Cmdlet unavailable | Use net localgroup to list groups, then net localgroup "GROUP_NAME". Domain membership is a separate query. |
