## Inspect the account and direct memberships

**Run in:** Windows PowerShell. **Requires:** ActiveDirectory module and permitted directory access; replace student

```powershell
Import-Module ActiveDirectory
Get-ADUser student -Properties SID,MemberOf,PrimaryGroupID,Enabled,Description
Get-ADPrincipalGroupMembership student | Select-Object Name,GroupScope,GroupCategory,SID
```

**What the result establishes:** Account properties and group objects to investigate; this is not a complete effective-access decision.

**Next check:** Inspect one interesting group directly and recursively, preserving intermediate links.

## Resolve a group's nested members

**Run in:** Windows PowerShell. **Requires:** A resolvable group identity and an authenticated directory session.

```powershell
Import-Module ActiveDirectory
Get-ADGroupMember -Identity 'GROUP_NAME' -Recursive
```

**What the result establishes:** Distinguish a group's object properties, direct members and recursively resolved membership.

**Next check:** Use direct membership queries to reconstruct each edge and verify the resource permission granted to that group.

## Commands

**Windows PowerShell**

```powershell
Import-Module ActiveDirectory
Get-ADGroup -Filter * | Select-Object Name
Get-ADGroupMember -Identity "Domain Admins"
```

## If it fails

| Symptom | Check |
| --- | --- |
| Module or DC lookup fails | Use native queries for baseline identity and fix module/DC discovery before interpreting an empty result. |
| Recursive output is mistaken for a complete membership path | A group name is not the same as a permission; verify where that group is granted access and whether the current token includes it. |
