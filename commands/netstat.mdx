## Match Windows listeners to process IDs

**Run in:** Windows cmd.exe. **Requires:** A Windows shell on the machine that owns the listeners.

```console
netstat -ano -p tcp
```

**What the result establishes:** Distinguish listening sockets from established connections and correlate PIDs with processes.

**Next check:** Map the PID with tasklist and compare bind address, firewall policy and the route from the client.

## Connections and PIDs

**Windows — cmd.exe**

```cmd
netstat -ano
```

TCP LISTENING identifies a listener; UDP has no equivalent state column.

## TCP listeners

**Windows — cmd.exe**

```cmd
netstat -ano -p tcp | findstr LISTENING
```

LISTENING is the English output label. Inspect unfiltered output on other language installations.

## If it fails

| Symptom | Check |
| --- | --- |
| A listener exists but remote connections fail | A loopback-bound service is not remotely exposed; IPv4/IPv6 binding and the host where the command ran matter. |
| A port is listening but remote access fails | Check its bind address, firewall and routing. A listener on 127.0.0.1 is local-only. |
