## Current operation: Match Windows listeners to process IDs

**Run in:** Windows cmd.exe. **Requires:** A Windows shell on the machine that owns the listeners.

```console
netstat -ano -p tcp
```

**Read the result:** Distinguish listening sockets from established connections and correlate PIDs with processes.

**If A listener exists but remote connections fail:** A loopback-bound service is not remotely exposed; IPv4/IPv6 binding and the host where the command ran matter.

**Next check:** Map the PID with tasklist and compare bind address, firewall policy and the route from the client.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Example 1: Connections and PIDs

Run in: **Windows — cmd.exe**. TCP LISTENING identifies a listener; UDP has no equivalent state column.

```cmd
netstat -ano
```

### Example 2: TCP listeners

Run in: **Windows — cmd.exe**. LISTENING is the English output label. Inspect unfiltered output on other language installations.

```cmd
netstat -ano -p tcp | findstr LISTENING
```

**A port is listening but remote access fails** — Check its bind address, firewall and routing. A listener on 127.0.0.1 is local-only.
