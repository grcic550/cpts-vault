## Identify the artifact and the privilege boundary

Local SAM/LSA extraction, LSASS inspection, offline hive parsing and DCSync are different operations. Start by naming the source host, identity, available privileges, and exact artifact you need for the exercise. A local administrator on a member server does not automatically have directory-replication rights.

### Establish the current context

```powershell
whoami /user
whoami /groups
whoami /priv
hostname
```

Record whether this is a local or domain identity and whether the current process is elevated. Protected processes and credential-isolation controls can restrict access even when a group membership looks promising.

### Local and offline material

```bash
# Parse already acquired lab registry hives locally.
impacket-secretsdump -sam SAM -system SYSTEM -security SECURITY LOCAL
```

The SYSTEM hive is required to interpret the corresponding protected material; use hives from the same host/snapshot. An incomplete or mismatched artifact set can produce failures unrelated to the account password.

For an authorized remote local-account extraction with the required host rights:

```bash
impacket-secretsdump 'DOMAIN_FQDN/ADMIN_USERNAME@TARGET_IP'
```

Read which extraction path the tool selected. Keep its outputs separated by host and account type, and do not treat every hexadecimal field as the same kind of credential.

### Verify replication rights before DCSync

Use the ACL workflow to inspect the domain naming context and effective replication permissions. The relevant combination of directory replication rights must apply to the domain object. Membership names alone are weaker evidence than the actual effective right.

```bash
# Target one lab account after establishing replication authorization.
impacket-secretsdump 'DOMAIN_FQDN/USERNAME@DC_FQDN' -just-dc-user LAB_TARGET_USER
```

This is a directory-replication operation, not an ordinary read of a local SAM file. Save the exact operation and returned account so its scope is clear.

### Classify what was recovered

| Material | Appropriate next question |
| --- | --- |
| Plaintext password | Which account/domain/service does it belong to, and is it current? |
| NT hash | Does the intended service permit the corresponding NTLM authentication path? |
| NetNTLM challenge/response | Is an offline recovery or an applicable live relay scenario relevant? |
| TGT/service ticket | Which principal, realm, service, cache and validity period does it represent? |
| Certificate plus private key | Which identity mapping and authentication service accept it? |

Use one relevant validation instead of spraying recovered material across every host. On failure, check account scope/state, protocol support and artifact type. Preserve evidence securely in the lab notes, and retain the original privilege/context explanation alongside any extraction recipe.

Distinguish local SAM/LSA extraction, an offline hive operation and directory replication; record exactly which artifact was returned.
