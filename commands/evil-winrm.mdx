## Check WinRM access with a known credential

**Run in:** Kali. **Requires:** WinRM reachable on the chosen transport and an account allowed to use its endpoint; add -S for a configured HTTPS endpoint.

```bash
evil-winrm -i TARGET_IP -u 'DOMAIN\USER' -p 'PASSWORD'
```

**What the result establishes:** A successful session identifies a WinRM-authorized account; use whoami and privilege checks to establish its actual token.

**Next check:** Check endpoint authorization and the actual remote token; test a second network hop separately instead of assuming credentials are delegated.

## Commands

**Kali**

```bash
evil-winrm -i TARGET_IP -u USER -p 'PASSWORD'
evil-winrm -i TARGET_IP -u USER -H NT_HASH
# HTTPS
evil-winrm -S -i TARGET_IP -u USER -p 'PASSWORD'
```

## If it fails

| Symptom | Check |
| --- | --- |
| SMB authentication works but WinRM denies the session | WinRM reachability and authorization differ from SMB. The current remote token may not carry credentials for a second network hop. |
