---

## 🧭 Guiding principles

1. **Module → Box → Write-up loop.** Don't batch modules. Finish 2–3 related modules, then apply them to 2–3 boxes, then write notes. Repeat.
2. **Notes are the product, not the certificate.** The act of writing clean technical + non-technical docs is what imprints the knowledge. You're building a reference library you'll use for 10 years.
3. **Break things, don't just read.** If a module has a lab at the end of a section, do it. If it has a skills assessment, do it twice — once following the module, once from scratch a week later.
4. **Take the exam only after AEN is done.** Attacking Enterprise Networks (AEN) is the strongest single predictor of exam readiness.
5. **The exam is 10 days (7 days + 3 for report).** Don't underestimate the report — it's 40% of your grade. Start practicing documentation from Day 1, not Week 20.

## ⚔️ Phase 4 — Pro Labs + exam (Weeks 27–33)

**Goal:** get exam-ready by simulating the real multi-host environment.

### Order matters

#### Week 27–29: Dante Pro Lab
- **Why first:** Dante is beginner-friendly, emphasizes **pivoting + service exploitation**. Low AD content. Builds stamina for long engagements.
- **Approach:** 14 machines, ~2–3 weeks. Try WITHOUT walkthroughs first; use community write-ups only when stuck >2 hours.
- **Cost:** ~$45–50 for 1 month cubicle access.
- [ ] Pick a weekend to dedicate 8–10 hrs for the first few boxes

#### Week 30–32: Zephyr Pro Lab
- **Why second:** Zephyr is mostly AD-based and IS the closest thing to the actual CPTS exam. Most reviews rank it 9/10 for exam prep.
- **Approach:** treat as a dry-run. Write a full report.
- **Cost:** ~$45–50 for 1 month.
- [ ] Write executive summary + full technical report when done

#### Week 33: Attacking Enterprise Networks (AEN) module
- Final CPTS path module. Simulates the exam. Do this LAST.
- If you crush AEN without hand-holding, you're ready.

#### Week 34 (buffer): Mock exam week
- [ ] Pick 3 active medium HTB boxes + 1 hard. Give yourself 7 days. No walkthroughs.
- [ ] Write a pretend report in the HTB report format.
- [ ] If you finish all 4 with complete reports → schedule the exam.

### Exam Day strategy (do NOT improvise this)

> **The exam format (10 days)**
> - 7 days: compromise the environment (13+ machines typical).
> - 3 days: write the report.
> - Pass: **≥85 / 100** machines pwned + the report must demonstrate methodology and be professional.

**Plan for exam week:**
- **Day 0:** read scope document slowly, twice. Build a `scans/` folder, a `creds.md`, a `hosts.md`.
- **Day 1–2:** external + initial foothold. Enumerate EVERYTHING. Do not rush.
- **Day 3–5:** pivot + AD attacks. Track every credential, every NTLM hash, every service.
- **Day 6:** sweep for missed low-hanging fruit (print servers, backup shares, scheduled tasks).
- **Day 7:** finalize flags + screenshots. STOP hacking end of Day 7.
- **Day 8–10:** write the report. 40% of your grade. Don't cheap out.

## 📝 Documentation rhythm (do this weekly, not at the end)

| When | What |
|:---|:---|
| After each module | 1-page technical summary + key commands in `Modules/[N]_[name].md` |
| After each box | Full walkthrough in `Boxes/[name].md` using box template |
| End of each phase | Update `Methodology.md` with your personal playbook |
| Every Friday | Fill `Weekly_Log.md` — what worked, what stuck, 3 things to review |

> **Why writing matters for CPTS**
> The report is 40% of the exam score. Students who pass the 85% machine threshold and fail the report are the most common failure mode. Practicing reports weekly (not cramming at Week 30) is the single biggest reliable predictor of passing.

## 🧠 Anti-procrastination rules (read before you start)

1. **Box time-boxing.** If you're stuck on a box for 3 hours with zero progress, take an official hint. If still stuck after 5 hours total, read the walkthrough but re-do the box from memory later. Your goal is **learning**, not pride.
2. **"One module open at a time."** Starting a new module before finishing the previous one is the #1 way people never finish the path.
3. **IppSec videos > random YouTube.** Watch one IppSec video per week for retired boxes. His methodology is gold.
4. **No Windows VM? No real practice.** Most AD boxes REQUIRE a Windows attacker box OR Kali with PowerShell tools (impacket, kerbrute, etc.) correctly set up. Fix this in Phase 0.
5. **Track stuck points.** When you're confused, write it down. Review "stuck points" list weekly. Most "hard" things are just unfamiliar things.

You mentioned Web Exploitation + Active Directory as interests. Natural next steps:
