## First test — affected page content

```html
<!--#echo var="DATE_LOCAL" -->
```

Compare the raw response with the literal directive. A file extension such as .shtml is a clue, not proof that SSI is enabled.

## Command execution check — only when exec is enabled

```html
<!--#exec cmd="id" -->
```

## Why common examples fail

- The input must reach content parsed for SSI; a normal reflected HTML field is insufficient.
- IncludesNOEXEC disables exec even when other SSI directives work.
- `include virtual` resolves a server URL, not an arbitrary filesystem path. `/etc/passwd` in that attribute does not inherently read the operating system file.
- `include file` is relative to the current document and is subject to path restrictions.

Record which directive actually executed before moving to [shell setup](/commands/web-shell-to-terminal).
