## Use names, realm and ticket scope consistently

When NTLM is unavailable, start by making Kerberos prerequisites explicit: correct domain/realm, resolvable service hostname, reachable KDC, acceptable clock agreement, and an identity or ticket valid for the requested service. A password that works against one service is not proof that the next client has the correct Kerberos context.

### Establish DNS and time

```bash
dig @DC_IP DC_FQDN A
dig @DC_IP _kerberos._tcp.DOMAIN_FQDN SRV
date -u
```

```powershell
Resolve-DnsName DC_FQDN
w32tm /query /status
klist
```

Check the lab's intended DNS resolver and realm configuration. A hostname in /etc/hosts can solve an address lookup but does not configure every aspect of KDC/realm discovery.

### Obtain and inspect a ticket

```bash
kinit USERNAME@REALM.UPPERCASE
klist
```

Alternatively, for an Impacket-produced cache:

```bash
impacket-getTGT 'DOMAIN_FQDN/USERNAME' -dc-ip DC_IP
export KRB5CCNAME='/absolute/path/USERNAME.ccache'
klist
```

Use the filename the tool actually produced. Confirm the principal, validity and realm. The shell's KRB5CCNAME must be visible to the client process you run next.

### Use a matching service hostname

```bash
nxc smb TARGET_FQDN -d DOMAIN_FQDN -u USERNAME -k --use-kcache
impacket-smbclient 'DOMAIN_FQDN/USERNAME@TARGET_FQDN' -k -no-pass
```

Inspect the installed client's support for the authentication options. The service principal must match the intended destination. A ticket for one account or service is not a universal replacement for arbitrary credentials.

| Error class | Check |
| --- | --- |
| Cannot locate KDC | Realm configuration, DNS SRV answers, explicit DC selection |
| Clock skew | Workstation, pivot and DC time sources |
| Principal unknown | Domain, account spelling and service hostname/SPN |
| Ticket expired or not yet valid | Cache identity and validity period |
| Authentication succeeds, access denied | Resource authorization and current token |
| First host works, second hop fails | Credential delegation and session authentication design |

A remoting session does not automatically carry reusable credentials to another server. Treat a second hop as a separate authentication design, using the permitted explicit credential or delegated mechanism in the lab. Retain the original ticket and command context when debugging.

## Kali — obtain and inspect a ticket

```bash
impacket-getTGT 'DOMAIN_FQDN/USER' -dc-ip DC_IP
export KRB5CCNAME='/absolute/path/USER.ccache'
klist
```

The first command prompts for the password. Replace the cache path with the file actually written. A ticket is an authentication credential, not proof of administrator rights.

## Connect using that cache

```bash
impacket-smbclient -k -no-pass 'DOMAIN_FQDN/USER@HOST_FQDN' -dc-ip DC_IP
```

Modern Samba also supports Kerberos:

```bash
smbclient '//HOST_FQDN/SHARE' --use-kerberos=required --use-krb5-ccache=/absolute/path/USER.ccache
```

Prefer FQDNs that match the service identity. Do not replace the service name with an IP merely because the IP is reachable.

## If it fails

| Result | Check |
| --- | --- |
| Cannot contact KDC | Routing, DNS/KDC discovery, realm configuration, and port 88 access. Impacket's explicit DC option differs from native Kerberos configuration. |
| Clock skew | Compare client time with the lab DC, including date and timezone. |
| Principal unknown | Correct realm, target FQDN, and registered service identity. |
| Cache not found / expired | KRB5CCNAME, file ownership, cache type supported by that tool, and klist expiry. |
| Access denied after authentication | Service authorization, share permissions, and account restrictions. |
