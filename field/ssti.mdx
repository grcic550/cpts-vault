## Test an input that is rendered into a page

Send each test separately and compare the raw HTTP response with an ordinary baseline:

```text
{{8*8}}
${8*8}
```

A computed result is evidence to investigate; a generic server error alone does not prove template injection. Client-side JavaScript can also alter what the browser displays.

## Next checks

| Observation | Next step |
| --- | --- |
| Input returned literally | Check encoding, reflection context, and whether the value is actually part of a template. |
| Expression evaluated | Identify the engine from syntax, application stack, and controlled comparisons. |
| One engine-specific expression fails | Check version, exposed objects, and sandbox; do not assume every public payload works. |
| Session or CSRF protection | Preserve the request's authentication and token when repeating a test. |

Template evaluation, file access, and OS execution are separate capabilities. Engine identification comes before choosing a payload from the detailed reference. Capture the original request, modified input, and raw response in your box notes.

## Offline template-engine identification matrix

Test benign mathematical/string probes one at a time and match the evaluated behavior and backend stack before selecting an engine-specific object chain:

| Backend Stack | Template Engine | Benign Identification Probe | Expected Evaluated Result | Key Context / Sandbox Notes |
| --- | --- | --- | --- | --- |
| **Python** (Flask / Django) | **Jinja2** | `{{7*'7'}}` | `7777777` | `{{config.items()}}` inspects Flask config; differs from Twig where `{{7*'7'}}` returns `49` |
| **Python** | **Mako** | `${7*7}` | `49` | Uses `${...}` expression blocks and `<% ... %>` Python blocks |
| **PHP** (Symfony / Craft) | **Twig** | `{{7*'7'}}` / `{{_self}}` | `49` | Numeric coercion (`7*'7' -> 49`) distinguishes Twig from Jinja2 (`7777777`) |
| **PHP** | **Smarty** | `{7*7}` or `{$smarty.version}` | `49` / version string | Single-brace `{...}` syntax; check Smarty v3 vs v5 security policy |
| **Java** (Spring) | **FreeMarker** | `${7*7}` or `<#assign x=7*7>${x}` | `49` | Check `Configuration.setNewBuiltinClassResolver` sandbox restrictions |
| **Java** (Spring Boot) | **Thymeleaf** | `__${7*7}__::.x` or `*{7*7}` | `49` | Often triggered in view-name routing, URL path fragments, or `th:text` expressions |
| **Java** | **Velocity** | `#set($x=7*7)$x` | `49` | Uses `#set` directives and `$variable` references |
| **Ruby** (Rails / Sinatra) | **ERB** | `<%= 7*7 %>` | `49` | Standard embedded Ruby tags (`<%= ... %>`) |
| **Node.js** (Express) | **Pug / Jade** | `#{7*7}` | `49` | Indentation-based template syntax using `#{...}` interpolation |
| **Node.js** | **EJS** / **Handlebars** | `<%= 7*7 %>` / `{{#with this}}` | `49` / context output | Handlebars is logic-less by default unless custom helpers or prototype gadgets exist |

## Automated verification (`tplmap` / `SSTImap`)

When manual arithmetic confirms server-side template evaluation and lab rules permit automated verification:

```bash
# Verify SSTI parameter and identify template engine with SSTImap
sstimap -u 'http://TARGET_IP/page?name=test'
```
