## Identify the account behind the service

Use this guide when you find an SPN, a service logon identity or a managed service account. Determine which kind of account it is, which service uses it, where that service runs and what access the account has. An SPN is an identity mapping for a service; it does not establish a weak password or administrative rights.

### Find the identity and service association

```powershell
Import-Module ActiveDirectory
Get-ADUser -Filter {ServicePrincipalName -like '*'} -Properties ServicePrincipalName,Description |
  Select-Object SamAccountName,ServicePrincipalName,Description
Get-ADUser svc_app -Properties ServicePrincipalName,MemberOf,PasswordLastSet,Enabled,SID
Get-CimInstance Win32_Service | Select-Object Name,StartName,State,PathName
```

Replace `svc_app` with the observed identity. The service inventory describes the host on which you execute it. User-account SPN enumeration does not enumerate every computer/service account, and an SPN can be stale. Correlate the directory entry with the actual service before choosing a credential or permission branch.

### Distinguish managed service accounts

```powershell
Get-ADServiceAccount -Filter * -Properties ServicePrincipalNames,PrincipalsAllowedToRetrieveManagedPassword |
  Select-Object Name,ObjectClass,ServicePrincipalNames,PrincipalsAllowedToRetrieveManagedPassword
Get-ADServiceAccount 'gmsa_app' -Properties PrincipalsAllowedToRetrieveManagedPassword,MemberOf,SID
```

These commands require the AD module and directory access. Inspect which principals are permitted to retrieve the managed password, then resolve their membership and object rights. Reading the account's ordinary metadata does not prove the current identity can retrieve its password. Do not treat a missing property or an access-denied response as an empty permission set without checking the query context.

### Connect identity privileges to the service

| Observation | Useful next question |
| --- | --- |
| SPN on an ordinary user | Which service/host owns it, and is the association current? |
| Service runs as a domain account | What resource access and local privileges does that account actually have? |
| gMSA retrieval principal is a group | Is the current identity effectively included and authorized? |
| Service binary/configuration is writable | Who executes it, what exactly is writable, and what legitimate trigger exists? |
| Account has unusual group membership | Which specific permission does that membership grant? |

Do not combine account control, filesystem control and service-control rights into one assumption. Record the account SID, service host, logon identity, SPNs, relevant groups/rights and the next condition to validate. Follow [group relationships](/field/ad-groups) or the [Systems methodology](/pivoting/methodology) according to the evidence.

## Windows — AD module

```powershell
Get-ADServiceAccount -Filter * -Properties PrincipalsAllowedToRetrieveManagedPassword,ServicePrincipalNames |
  Select-Object Name,PrincipalsAllowedToRetrieveManagedPassword,ServicePrincipalNames
Get-ADUser -LDAPFilter '(servicePrincipalName=*)' -Properties ServicePrincipalName |
  Select-Object SamAccountName,ServicePrincipalName
```

## Choose the right branch

| Result | Interpretation / next step |
| --- | --- |
| Ordinary user with an SPN | See the existing Kerberoasting notes. Cracking feasibility depends on password strength and encryption type. |
| Managed service account | Managed passwords are designed to be long and rotated; do not equate an SPN with an easily crackable password. |
| gMSA retrieval principals | Resolve the permitted principals and effective group membership before expecting access to msDS-ManagedPassword. |
| Service runs as an account | Inspect local service configuration and that account's actual rights; the name alone does not imply admin. |

A readable gMSA object does not imply that its managed-password attribute is readable. An empty result can be an ACL or connectivity issue rather than a missing account.

Use [GetUserSPNs](/commands/getuserspns), [bloodyAD](/commands/bloodyad), or your [Windows credential notes](/password-attacks/credential-hunting-in-windows) for the matching task.
