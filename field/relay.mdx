## Kali — inspect the SMB destination

```bash
nmap -Pn -p 445 --script smb2-security-mode TARGET_IP
```

Read whether signing is **required**, not simply supported. A destination requiring SMB signing blocks the usual SMB relay path to that destination.

## Before starting a listener

| Need | Verify |
| --- | --- |
| Incoming authentication | Which lab system will authenticate, with which account, and over which protocol? |
| Reachable destination | The relay host must reach the destination service. |
| Eligible protocol | SMB signing, LDAP signing/channel binding, and HTTP extended protection are different controls. |
| Useful account rights | Relayed authentication does not add privileges the account lacks. |
| Free listening port | Two tools cannot both own the same address and port. |

Open [ntlmrelayx commands](/commands/ntlmrelayx) or the saved [AD CS certificate lab](/password-attacks/pass-the-certificate). Collecting a NetNTLM response for offline cracking and relaying an authentication exchange are separate techniques.

If you receive authentication but no useful session, check the destination protection and authorization before assuming the listener is broken.
